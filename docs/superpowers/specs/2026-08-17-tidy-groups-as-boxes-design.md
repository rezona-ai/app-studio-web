# 分组框作为整体参与一键整理（取消类型分带）

日期：2026-08-17
状态：待批准（三条决策由 Nick 逐条确认：框当原子盒子 / 方案 B 取消分带 + 跨框边提升 / 不引 elkjs）
前置：`2026-08-05-canvas-groups`（分组本体、决策 3 定下「框内成员不参与整理」）、`2026-08-14-migrate-taluna-canvas-line-design`（画布线迁入）

## 目的

迁入后实机反馈：**用户圈了组，反而失去了整理能力**。

现状（`store/actions.ts` 的 `tidyCanvas` + `lib/card-layout.ts` 的 `tidyLayout`）：框内成员整批剔除、框本身当作**避让障碍**传进去，整理块整体落到「确实挡路的那些框」的最低底边之下。于是画布上出现两套各自为政的坐标——框和它的成员停在用户手摆的位置，散卡被排成整齐的类型分带并被推到框下方。框越多，整理后的画布越像「上半张手摆 + 下半张自动」。

本回合让框**作为一个整体参与整理**：框是排队单元，框内不动。

## 参考实现（LibTV，2026-08-17 实测）

同类产品 LibTV 的画布同样是 React Flow，整理入口是 ⌥⇧F。其 `computeElkRootNodeUpdates` 的做法（读的是线上 chunk）：

1. **只排 `!parentId` 的根节点**：框是根节点、成员是 RF 子节点，故框内相对布局天然不动、框一移动成员自动跟随。
2. **边提升到根**：沿 parentId 向上爬（防环上限 256）把边两端换成各自的根祖先，「框内卡 → 框外卡」变成「框 → 卡」；同框内部的边成自环丢弃、重复边去重。
3. **并查集拆弱连通分量**，分量内按 (y, x)、分量间按最小 y 再最小 x 排序（位置记忆的确定性来源）。
4. **每分量跑 ELK**：`layered` / `RIGHT` / `spacing.nodeNode=100` / `nodeNodeBetweenLayers=200`。
5. **分量货架铺放**：锚点取所有根节点当前 min(x)/min(y)，向右铺、超 3200 换行，间距 150，吸 12px 网格。
6. **只回报 position**——从不改框的 w/h；整理后弹「是否保留此次整理结果？还原 / 保留」。
7. 它**没有**类型分带这层。

我们照搬其 1/2/3/5/6 的语义，不照搬 4（见决策 5）与 7 的确认条（见「明确不做」）。

## 约束

- **位置归前端所有**：框几何（x/y/w/h）与卡坐标同一口径；服务端缺值不得覆盖本地。
- **框内不动、框尺寸只读**：整理不改任何框的 w/h，也不改成员相对框的偏移——容器模型下「几何是真相」，重排框内等于系统替用户重新组织了他圈出来的内容。
- `tidyLayout` 保持**同步纯函数、零新依赖**：整理仍在一次 `set` 内落定，撤销入栈与切项目竞态守卫不变。
- **一次 ⌘Z 全部回退**：卡坐标、框坐标、视口三者同一条撤销条目。
- **回写口径不变**：卡走批量端点 `batchUpdateCanvasItems`；框没有批量端点，逐个 `updateCanvasGroup` PATCH，fire-and-forget（同 `moveGroup`）。
- 占位卡（`pending_` 前缀）参与布局但**不回写**（沿用现状的 changed/moved 双判据）。

## 决策

### 决策 1：框是整理的原子盒子

框以 `(w, h)` 作为**一个固定尺寸节点**参与分量划分与货架铺放；框内成员**不参与落位**，而是按框的位移 delta 整体平移（复用 `canvas-group.ts` 的 `translateGroup` / `translatePositions` 语义，与拖框整组移动同一条路径）。

**输入契约**（新签名，照 LibTV 的「全量进、内部筛根」）：

```ts
tidyLayout(nodes: TidyNode[], boxes: TidyBox[]): { cards: Map<string, XY>; boxes: Map<string, XY> }
// TidyNode 增一个 groupId?: string —— 全部卡都传进来(含框内成员),
//   函数内部按 groupId 分流:无 groupId 的是排队单元,有 groupId 的**只贡献边**、不出现在 cards 里
// TidyBox: { id: string; w: number; h: number }
```

成员必须进函数：决策 2 的边提升需要它们的 `parentId` / `refIds` —— 「框内卡 → 框外卡」这条边只存在于成员一侧（我们的边方向是「被引用者 → 本节点」，故成员引用外部卡时，边只挂在成员身上）。函数返回两张表，`cards` 只含参与落位的框外卡；框内成员的新坐标由调用方按 `boxes` 的 delta 算，**不由布局函数产出**（它不知道成员现在在框内哪个位置，那是几何真相、不该被布局重新发明）。

- **空框照样参与**：它是用户圈出来的区域，跳过它等于允许别的卡压在它身上。
- **孤儿 groupId 的卡**（`groupId` 指向已不存在的框）按普通卡参与，沿用现状。
- 框的排序键与卡一致（当前位置的 y 再 x），保证「整理后大致还在原来那一带」的位置记忆。

### 决策 2：跨框引用边提升到框

建图前把每条边的两个端点映射成「该端点所属框的 id，或它自己」：

- 框内 → 框内：自环，丢弃（框内关系与整理无关）。
- 框内 → 框外 / 框外 → 框内：变成「框 ↔ 卡」的边，于是框与相连的卡进入同一连通分量、框在分层里占一列。
- 提升后重复的边去重。

收益：整理后跨框血缘仍读得出（框右侧紧挨着由它派生的产物），而不是一条横穿半个画布的连线。

### 决策 3：取消类型分带（方案 B）

`TIDY_ROW_KIND_ORDER` 与 `tidyLayout` 的 `kindOrder` 参数**一并退役**，整理只按血缘分量货架铺放（行宽阈值沿用 `MAX_ROW_WIDTH = 3200`、间距沿用 `COMPONENT_GAP`、吸附沿用 `SNAP_GRID = 10`）。

理由：分带按「分量根的 kind」归带，而框是混合类型的——框一旦入局，要么给框单独开一带（那条带里躺着与框相连的 video 卡，分带口径自相矛盾），要么按成员主类型归带（混合框归哪带纯属任意）。两条都让「一带 = 一个类型」这个读者预期失效，不如干脆放弃这层。

这是**产品可见的行为回退**：整理后不再能靠纵向位置扫读类型，改由类型过滤图例（`visibleKinds`）承担「只看视频」这类需求。

### 决策 4：`obstacles` 避让机制退役

框参与铺放后，「整理块整体落到挡路框的底边之下」这条避让既无必要也有害（框已经在队列里，再被当障碍会把自己推走）。删 `tidyLayout` 的 `obstacles` 参数与对应单测——**不留两套避障叠着**（反模式「堆叠废弃机制」）。

按「并存加新 → 原子切换 → 删旧」推进：新旧签名不可能并存（分带与框入局的口径互斥），故本回合一次切换，靠单测钉住新形态的每条不变式（不重叠、框内不动、分量相邻）。

### 决策 5：分层引擎沿用现有内核，不引 elkjs

现有 `tidyLayout` 已经是「分量化 DAG + 最长路径分层（列向右）+ Reingold–Tilford 行序 + 多父居中 + 货架铺放」，与 ELK 的 `layered/RIGHT` 同一形态；引 elkjs 要多 1.61 MB（min 后 1.59 MB，gzip 约 400 KB）的懒加载 chunk，且 `layout()` 是 Promise——整理从同步变异步，撤销入栈时机与「`await` 后校验 `currentProjectId`」都要重做，现有 tidy 单测基本作废。

代价记在这里：我们没有 ELK 的边交叉最小化，密集多父图的连线会比 ELK 乱一些。若将来实测确实读不了，再按「并存加新 → 原子切换」换引擎。

### 决策 6：撤销与回写

- **撤销**：`UndoEntry` 的 `positions` 条目新增 `groupGeoms?: { id: string; x: number; y: number }[]`（**不能复用已有的 `groups` 字段**——那个记的是归属还原 `{ id, groupId }`，语义完全不同）。`undo()` 按 type 分派时把框搬回原位；成员坐标已在 `positions` 里，故不需要再记成员。
- **回写**：卡沿用 `persistAssetPositions(moved)`；框对每个**真的动了的**框发一次 `updateCanvasGroup(pid, gid, { canvas_x, canvas_y })`，坐标 `Math.round`（后端 int 契约）。失败不回滚、不阻塞 UI（同 `moveGroup`）；框的 w/h 不在这次 PATCH 里。
- **零位移早退**：布局无变化（连点两次整理）时不入栈、不回写、不发请求——现有 `changed` 守卫扩展到「卡或框任一动过」。

## 成功标准

1. 含 3 张卡的框 + 两条散卡链：整理后框内三张卡的**相对位置**与框的 **w/h** 逐字节不变，框整体移动到货架位置。
2. 框内卡引用框外卡：整理后该卡落在框**右侧一列**（同分量、框有列位）。
3. 整理后**任意两个矩形**（卡-卡、卡-框、框-框）不重叠。
4. 画布上全部卡都在框里时，整理仍会摆放这些框（现状是 `rearranged.length === 0` 直接 return，什么都不做）。
5. 一次 ⌘Z 把卡坐标、框坐标、视口全部还原。
6. 占位卡参与布局，但不产生任何卡/框的回写请求。
7. 连点两次整理：第二次不入撤销栈、不发请求。
8. 仓内 `TIDY_ROW_KIND_ORDER` 与 `tidyLayout` 的 `obstacles` **零残留引用**（`grep` 为空）。

## 明确不做

- **框内重排 / 框尺寸自适应**：见约束二。
- **局部整理**（只整理某个分量，LibTV 的 `computeElkSubgraphLayoutForSeedNode`）：入口与选区语义要另设计，本回合不碰。
- **整理后「保留 / 还原」确认条**：⌘Z 已覆盖同一撤销语义（且连视口一起还原），再加一条浮层是第二套撤销入口。
- **折叠框**（`Group.collapsed`）：后端字段已有、前端本就不渲染，整理按展开尺寸处理。
- **新建节点落位算法**：`childPosition` / `cascadePosition` / `avoidOverlap` 原样，本回合只动整理。
