# 资产卡片生成占位视觉设计

## 背景

画布中的图像、视频、音频与 3D 资产在生成阶段缺少统一的视觉表达：图像、视频和 3D 使用类型纯色叠加 spinner，音频仅展示静态波形。等待时间较长时，这些状态既无法传达“内容正在逐步成形”，也与生成完成后的媒体卡片存在明显视觉断层。

## 目标与成功标准

- 为图像、视频、音频、3D 四种生成资产提供同一艺术语言、类型可辨识的占位图。
- 用克制的共享动效表达持续生成，不再以简单 spinner 作为主体反馈。
- 真实资产就绪时沿用现有 `anim-media-in` 淡入，形成占位图到内容的平滑交接。
- 上传进度覆盖层保持现状；本需求只替换无百分比时的生成占位态。
- 所有本地图片路径经过 `assetPath()`，适配 `/game` basePath。
- `prefers-reduced-motion: reduce` 下关闭位移、缩放与扫光，只展示静态占位图和可访问状态文案。

## 现状约束

- 四类节点分别由 `ImageNode`、`VideoNode`、`AudioNode`、`ThreeDNode` 渲染，外框统一由 `NodeCard` 承担。
- 卡片媒体区高度不同，图像 150px、视频 132px、音频 72px、3D 140px；占位图需要允许 `object-fit: cover` 裁切。
- 状态来源仍是 `asset.status === 'generating'`，不新增 store 字段或生成阶段协议。
- `NodeCard` 的上传进度层位于子节点上方，必须继续覆盖新的占位视觉。
- 项目禁止一次性硬编码颜色和遗漏 reduced-motion 的动画。

## 方案比较

### 方案 A：只增强 CSS 骨架

在现有纯色背景上增加渐变、波纹和 shimmer。

- 优点：包体小、实现简单、主题适配天然。
- 缺点：四类资产仍缺少具象识别，无法满足“四张占位图”的明确需求。

### 方案 B：四张类型占位图 + 共享 CSS 动效（推荐）

生成四张统一风格的抽象 3D 插画，分别用取景框、电影帧、声波、网格模型表达图像、视频、音频、3D；在其上叠加共享的慢速景深漂移、柔光扫过和状态光环。

- 优点：类型识别强；静态资源可压缩缓存；CSS 动效成本低；可完整支持 reduced-motion。
- 缺点：增加四个图片资源；不同卡片比例会有少量裁切。

### 方案 C：四段循环视频或 Lottie

为每类资产制作独立循环动画。

- 优点：表现力最强。
- 缺点：资源与解码成本高；多卡并行生成时耗电和 GPU 压力显著；额外引入运行时或媒体生命周期处理，不符合 YAGNI。

## 推荐设计

采用方案 B。

### 视觉语言

- 统一使用深色柔雾舞台、半透明材质、柔和体积光和品牌青能量轨迹。
- 每张图保留对应资产类型色作为局部主色：图像蓝、视频橙、音频绿、3D 紫。
- 不出现文字、logo、水印或具体品牌元素，避免缩小裁切后产生噪声。
- 主体居中，四周留安全区，兼容 180×150 至 210×72 的媒体区裁切。

### 动效编排

1. 占位图复用 `anim-media-in`，以 200ms 淡入进入生成态。
2. 半透明柔光层复用 `skeleton-shimmer` 横向掠过，表达持续处理。
3. 中央状态光环复用 `brand-float` 做低幅漂浮，并承载 `role="status"` 与生成中文案。
4. 真正媒体就绪后继续由现有 `anim-media-in` 交叉淡入；不增加额外状态机或卸载延迟。

不新增专用 keyframes，避免画布动效语汇继续分叉。

### 组件边界

新增共享的 `GeneratingPlaceholder` 组件，仅接收资产类型、高度类名和可选 className：

- 在组件内部把类型映射到本地占位图路径和类型色。
- 统一渲染图片、暗部渐变、扫光层和状态光环。
- 四个节点不再维护各自 spinner / 静态生成占位实现。
- 图像节点在“重新生成但旧图仍存在”时继续显示旧图，并叠加统一生成覆盖层，避免内容突然消失。

## 无障碍与性能

- 只有状态光环暴露 `role="status"`，图片使用空 `alt`，防止重复朗读。
- 本地占位图使用 `loading="eager"` 和 `decoding="async"`；它们尺寸小且只在生成卡片出现时挂载，优先避免状态闪白。
- 复用动画只使用 `transform`、`opacity` 和 `background-position`，避免布局抖动。
- reduced-motion 下所有新动画关闭，静态占位图保持信息完整。

## 非目标

- 不修改后端生成进度协议，不伪造百分比。
- 不改变上传阶段已有的真实百分比进度层。
- 不重做错误态、卡片外框、生成完成后的播放器或 3D 预览。
- 不为文本资产增加生成占位图；本需求只覆盖当前四种媒体生成资产。
