# 画布资产列表视图（左侧浮层面板）

> 状态：设计稿 · 2026-08-04
> 关联：P1 第二项。P0 三块已全部回合（撤销 / 搜索跳转 / 创作溯源两步）。
> 同期未做：P1 的「框 / 分组」（卡在后端无容器实体）、「批量操作 + 对齐吸附」。

## 目的

**空间导航擅长表达关系，不擅长穷举清查。** 画布是目前唯一的资产入口，于是这类问题无解：

- 「这个项目一共有哪些音频？」
- 「最近生成的那批图在哪？」
- 「哪些资产是我上传的、哪些是 agent 生成的？」

只能靠肉眼在画布上扫。资产上百后（`MAX_ROW_WIDTH = 3200` 的货架布局横向能铺很远）这事实上做不到。

顺带补一个旧缺口：**画布搜索只能高亮/减淡，不能真筛**（`buildRfNodes` 传 query 只改卡片透明度）。列表里搜索是真筛掉，搜到的东西终于能成一份干净结果集。

## 约束

1. **左侧浮层面板，两行紧凑式行**。外观与右侧属性面板对称（圆角浮层 + 四周留边 + popover 阴影 + backdrop-blur），左右呼应；上下留边正好让开顶部搜索栏与底部工具条，**工具条不为它让位**。
   > 形态经历过两次修正，记录以免后人重走：最初定的是**底部抽屉 + 五列横向表格**（理由是表格宽而矮、与右侧属性面板不抢横向空间）。真机看过后改为左侧。改动带出两个必然结论：① 面板宽仅 ~300px，五列表格塞不下 → 行改两行紧凑式（首行缩略图 + 名称，次行 `类型 · 来源`，就绪态不显示、只在失败时出红字）；② 没有表头可点了 → 排序入口收进面板头部。左右分居后，属性面板当初为躲底部抽屉加的 `bottomOffset` 也一并撤掉。
2. **与画布全联动**：共享 `visibleKinds` 过滤器、共享搜索词、**选中态双向同步**。列表不自带第二套搜索框，避免「我刚才搜的是哪个」。
3. **不新增后端契约**。排序所需的创建顺序取 `CanvasItemData.id`（数据库自增，单调递增）——目前映射层把它丢了，本次补进 `Asset`。
4. **不做时间列**（本轮）。canvas item 当时没有 `created_at`；`provenance.at` 只覆盖本次改动后前端生成的那批，做成列会大半为空（与属性面板「无溯源整段不渲染」同一原则）。**排序可以按创建顺序，展示不做时间。**
   > ⚠️ **2026-08-08 已推翻前提**：后端 `CanvasItemData.created_at` 已下发并进了前端契约，
   > 时间改以「相对时间 + 按天分组」呈现（不是列，也不新增排序维度 —— 与 `seq` 语义重叠）。
   > 见 `specs/2026-08-08-canvas-time-dimension.md`。
5. **面板不是第二个真相源**：所有操作（选中 / 删除 / 重命名）都走既有 store action，列表只是另一个订阅者。
6. UI 复用既有令牌 / 组件 / 动效，不新增按钮种类、不写一次性 keyframes。

## 成功标准

1. 底部工具条有开关（同 minimap / 属性面板那两枚的写法），开合状态**持久化**。
2. 面板宽度可拖拽（默认 300px，上限为画布宽的 45% —— 横向还要与右侧属性面板 280px 分地）；**工具条位置不受影响**。
3. 行内容：缩略图 · 名称（首行），`类型 · 来源`（次行灰字），失败态额外出红字。头部有排序控件，可按 **创建顺序（默认，最新在前）/ 名称 / 类型** 排序，点当前维度翻升降序。
4. 只列**当前可见类型**（受 `visibleKinds` 约束）且**命中搜索词**的资产 —— 搜索在这里是真筛，不是高亮。
5. 选中态双向：画布选中 → 列表行高亮并滚动到可见；列表点行 → 画布选中该卡并 `ensureVisible` 带进视口。
6. 列表行 hover → 画布对应卡片高亮（复用既有搜索命中的强调语汇）。
7. 多选：列表支持 ⌘/Shift 多选，与画布选区同步；右键沿用既有 `ContextMenu`。
8. 空态分两种：项目本就没有资产 vs 当前过滤/搜索无命中 —— 文案不同，后者给「清除筛选」入口。
9. 面板打开时画布交互不受影响（拖拽 / 缩放 / 双击新增照常）。
10. `pnpm lint` / `pnpm exec tsc --noEmit` / `pnpm test` / `pnpm build` 全绿。

## 现状要点（实现前必读）

- `CanvasItemData.id: number` 是数据库自增主键，但 `canvasItemToAsset` 只取了 `item_id`（字符串）作 `Asset.id`，数字 id **被丢弃**。本次补 `Asset.seq?: number` 承载它 —— 这是唯一能覆盖全部资产的创建顺序依据（`provenance.at` 只覆盖新生成的）。
- 过滤与搜索现状：`visibleKinds` 在 store；搜索词 `query` 是 `AssetCanvas` 的**局部 state**，只喂给 `buildRfNodes` 做高亮。列表要共享它 → **搜索词须上提到 store**。这是本需求唯一一处对既有结构的改动，需谨慎（`AssetCanvas` 的 ⌘K 聚焦、Esc 清空等行为不得回归）。
- 选中态已在 store（`selectedIds` + `setSelection`），双向同步天然可行。
- `Segmented`（`components/ui/Segmented.tsx`）是等分分段控件，用于排序切换不合适（等分 + 无升降序指示）；排序控件自己实现三个文字按钮 + 升降序箭头。
- `ensureVisible`（`lib/viewport.ts`）已注册，列表点行定位直接复用。

## 方案

### 1. 数据与状态

```ts
// store/types.ts
// Asset 增 seq?: number —— 服务端数字主键,唯一覆盖全部资产的创建顺序依据(见约束 3)

// UIState
listOpen: boolean;        // 面板开合,持久化(同 inspectorOpen)
listWidth: number;        // 面板宽度 px,持久化
canvasQuery: string;      // 搜索词从 AssetCanvas 局部 state 上提(画布高亮与列表筛选共用一份)
listSort: { by: 'seq' | 'label' | 'kind'; desc: boolean };   // 瞬态,不持久化
```

`seq` 只读不写：不进 `assetReference`（服务端自己有主键，回写它没有意义且会被无视）。

### 2. 纯逻辑下沉

⚠️ **命中判定不新写**。`lib/canvas-search.ts` 已有 `matchesQuery`，其注释明写「全画布唯一口径 —— 避免『高亮的』与『能跳到的』两套判定漂移」。本需求只做两件事：

1. 把它的搜索域从 `label + key` **扩到含 `provenance.req.prompt`**（用户往往记得「我当时写了什么」，而资产名多半是自动生成的串）。画布搜索因此也能按提示词搜到，是顺带的改进。
2. 空词语义两边天然相反 —— 画布命中集里空词=无命中（否则计数显示 47/47，与「未搜索」无法区分），列表里空词=列全部。差异是**调用方语义**，由 `asset-list.matchesListQuery` 包一层短路，**不污染那个唯一判定**。

新建 `src/lib/asset-list.ts`（无副作用、可单测）只放列表自己的东西：

- `matchesListQuery(asset, query)` —— 空词短路，非空委托给唯一判定。
- `filterAssets(assets, visibleKinds, query)`
- `sortAssets(assets, sort)` —— 三种排序 + 稳定次序（`seq` 缺失的历史资产**恒沉底且不随升降序翻转**，否则降序时一堆「未知顺序」会顶到最前）。

### 3. 组件

新建 `src/components/canvas/AssetListDrawer.tsx`：

- 位置：画布列内 `absolute left-5 top-16 bottom-24`，宽度受 `listWidth` 控制，右缘一条可拖拽把手（复用 Workspace 分隔条的手势写法）。
- 头部：标题 + 命中计数 + 排序控件（三维度平铺，点当前维度翻升降序）。
- 行：两行紧凑式，hover / selected 复用既有强调语汇。
- 行交互：点击 → `setSelection([id])` + `ensureVisible`；⌘/Shift 多选；右键 → 既有 `ContextMenu`。
- 空态两种（见成功标准 8）。
- 退场走 `useExitTransition`。

`ZoomBar` **不受影响** —— 面板四周留边已让开它，不必再传偏移。

## 取舍与明确不做

- **不做时间列** —— 见约束 4。
- **不做列显隐 / 字段配置** —— 行内容固定，YAGNI。
- **不做列表内改名 / 内联编辑** —— 右键菜单已有重命名，不重复造入口。
- **不做虚拟滚动** —— 画布资产量级（百级）用不上；真到千级再说，届时 `onlyRenderVisibleElements` 那套思路可复用。
- **不给列表单独的搜索框** —— 见约束 2。
- **不改画布搜索的高亮行为** —— 列表补的是「真筛」，画布上仍是高亮/减淡（那是空间视图里正确的做法，不能把没命中的卡直接从画布上抹掉）。
