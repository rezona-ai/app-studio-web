# 画布卡片：整卡拖拽 + 侧边跟随「+」设计稿

日期：2026-08-03
关联代码：`src/components/canvas/nodes/*`、`src/lib/derive-band.ts`（新）、`src/app/globals.css`

## 目的

画布卡片当前有两处手感问题：

1. **拖不动**：5 类卡片的媒体区都挂了 `nodrag` + `mousedown` 阻断（`ImageNode.tsx:26`、`VideoNode` ReadyBody、`AudioNode` PlayerBody、`ThreeDNode` ReadyBody），所以整张卡只有顶部 ~30px 的标题栏能拖。卡片越大，可拖区域占比越小。
2. **「从此生成」入口只在选中后才出现**：`+` 仅在 `soleSelected` 时渲染（`NodeCard.tsx:85`），派生一张卡必须先点选、再瞄准右边缘中点那颗 24px 的按钮，两步且靶点固定。

本次把交互模型改成「**未选中 = 对象态（整卡是拖拽把手，右侧带内跟随的 + 是唯一例外）；选中 = 内容态（媒体交互全开）**」，并让 `+` 在侧边触发带内跟随鼠标，靠近即可点。

## 约束（盘问结论）

- **C1 非选中态整卡可拖**：卡内任意位置按住即可拖动，单击=选中。图片放大、视频播放/放大、音频播放器、文本卡双击编辑**全部**在非选中态让位给拖拽（不做「播放类例外」）。选中后这些交互原样恢复。
- **C2 `+` 只贴右侧**：与既有 source 连接位、以及「从此资产生成」新卡向右派生落位的方向一致；左侧仍是 target 连接位，不出 `+`。
- **C3 `+` 完全跟随鼠标**：触发带内 `+` 的 x/y 都跟随指针（不是只沿边缘上下滑），观感是「粘在光标上的小把手」。
- **C4 触发带 = 贴着右边缘的一小块**：右边缘往内 6px、往外 64px，纵向只覆盖卡高**中段 60%**（上下各留 20%）。数值按实机反馈定稿（Nick 2026-08-03 圈定的范围）：初版「内 16 / 外 40 / 整卡高」在真机上跟随距离过大，且纵向覆盖整卡显得过于活跃。带元素在卡内，尺寸天然随画布缩放等比变化。
- **C5 选中态 `+` 常驻且可跟随**：选中态保留现有常驻 `+`（压在右边缘中点，对齐 Figma 219-3886）；指针进入触发带时它从中点滑到指针处，离开后滑回中点、**不隐藏**。非选中态则是「带内淡入 + 跟随，离开时复位到中点并淡出隐藏」。
- **C6 沿用既有令牌与动效语汇**：`+` 视觉、Tooltip、`openAddMenu` 行为一律不变；跟随/复位过渡走新增的一个 `.derive-plus-follow` 类（120ms + 标准进场缓动），并补进 `prefers-reduced-motion` 禁用列表。
- **C7 多选（≥2）不出 `+`**：延续「多选不逐卡冒出单选专属操作」的既有规则，多选态下悬停也不出。

## 成功标准

1. 非选中的图片 / 视频 / 音频 / 3D / 文本卡，从媒体区正中按住即可拖动；单击只选中，不打开预览 / 不播放 / 不进编辑器。
2. 选中同一张卡后，点图片 / 3D 快照打开全屏预览，视频可就地播放与放大，音频播放器可用，文本卡双击进编辑器 —— 与本次改动前一致。
3. 非选中卡：指针进入右侧触发带 → `+` 淡入并跟随指针；指针离开带 → `+` 滑回右边缘中点并淡出。
4. 选中卡：`+` 常驻中点；指针进带内跟随，出带滑回中点且始终可见。
5. 触发带落在卡外的部分点 `+` 可开「从此资产生成」菜单；带内落在卡上的部分按住仍能拖卡（`+` 不吃掉这次按压）。
6. `prefers-reduced-motion` 下跟随/复位无过渡（瞬移），功能不残。
7. `pnpm lint` / `pnpm exec tsc --noEmit` / `pnpm test` 全绿。

## 方案

### 采纳方案：触发带做成卡片内的子元素，`+` 仍留在 `NodeCard`

`NodeCard` 内新增一个不可见的触发带 `<span>`：`absolute`、`left: width - 6px`、宽 70px（6 内 + 64 外）、`top: 20% / bottom: 20%`（纵向中段 60%，卡高由内容决定故用百分比）。它是节点 DOM 的子元素，于是：

- **hover 判定主要交给浏览器**：`onPointerMove` / `onPointerLeave` 天然就是「进带 / 出带」，不需要任何视口坐标换算、不需要 canvas 级指针监听。
- **`+` 的位置换算只需带元素自身的矩形**：带左缘恰在卡片右边缘往内 6px，故 `scale = band.width / 70` 即当前画布缩放，`+` 的锚点（右边缘中点）在带内局部坐标为 `(6, 带高/2)`。指针 → 锚点偏移是一段纯几何，抽到 `src/lib/derive-band.ts` 单测。
- **但不能只信 `pointerleave`**：`+` 直径 24px、圆心压在指针上，会探出带边约 12px，而它是带的**子元素** —— 光标压在这圈探出部分上时 `pointerleave` 不触发，于是光标能一路把 `+` 往带外拽（棘轮效应，初版实机能拽到 150px 外）。故 `followOffset` 每次移动都自行判定指针是否已出带矩形，出带即返回 `null`（调用方复位并隐藏）。
- **拖拽语义天然正确**：带不挂 `nodrag`，所以在带上按下就是「在卡上按下」——选中 + 拖动，C1 在卡外那 64px 也照样成立（等于把拖拽把手往右扩了 64px）。
- **`+` 仍在节点内**：视觉、缩放行为、Tooltip、z 层级全部沿用现状，不引入画布级浮层与第二套 `+` 实现。

`+` 的渲染结构改为「锚点层 + 偏移层」两层嵌套：

- 外层锚点：`absolute right-0 top-1/2 -translate-y-1/2 translate-x-1/2`（= 现状），**不过渡**，因此画布平移 / 缩放时 `+` 与卡片边缘严丝合缝、无拖尾。
- 内层偏移：`transform: translate(dx, dy)`（卡内 px），**带 120ms 过渡**，负责「滑到指针 / 滑回中点」。

可见性与命中：

| 状态 | 可见 | 位置 | 可点 |
|---|---|---|---|
| 非选中 · 指针在带外 | 否 | — | — |
| 非选中 · 指针在带内 | 是（淡入） | 跟随指针 | 指针在卡外侧时可点；在卡内侧时 `pointer-events: none`（让位给拖拽，见下） |
| 非选中 · 刚离开带 | 退场 180ms（淡出） | 滑回中点 | 否 |
| 单选本卡 · 指针在带外 | 是（常驻） | 右边缘中点 | 是 |
| 单选本卡 · 指针在带内 | 是 | 跟随指针 | 同上按内外侧判定 |
| 多选（≥2） | 否 | — | — |

**`+` 落在卡内侧时置 `pointer-events: none`**：`+` 直径 24px 且圆心就在指针上，若始终吃事件，则触发带里靠卡内那 6px 就按不到卡片，与 C1「任意位置可拖」冲突。故按指针是否越过卡片右边缘切换 `+` 的命中：卡内 → 透明（按下即拖卡），卡外 → 可点（按下 / 点击开菜单）。常驻态（指针不在带内）恒可点，与现状一致。

### 已知取舍

- **触发带在卡外的 64px 会「吸走」空白处的框选起手**：React Flow 的橡皮筋框选只在 `mousedown` 命中 `.react-flow__pane` 本身时启动（`Pane.onPointerDownCapture` 判 `event.target === container`），带元素是节点子元素，故卡右侧 64px 内起手不会框选，而是选中并拖动该卡。滚轮缩放 / 平移不受影响（wheel 照常冒泡到 pane），中键平移的表现与「在卡片上中键拖」一致。此项在盘问中已确认接受。
- **左右相邻卡间距 < 64px 时，两者的这块区域会互相叠一小段**：谁在上由节点 z 序决定 —— 邻卡在上则本卡触发带的最外侧几 px 失效（实机默认落位间距 60px，即最外 4–5px 变哑，无感）；本卡带在上则邻卡左缘那几 px 的点击会落到本卡。都只影响个位数 px，代价是最多误选一次，不引入额外机制去防。
- **`+` 随画布缩放等比放大缩小**（因为仍在节点内）：与现状及设计稿一致，代价是 10% 缩放下 `+` 很小；不为此单独做「恒定屏幕尺寸」的画布级浮层。

### 备选方案（未采纳）

1. **画布级 `+` 浮层**（单个 `+` 元素画在 pane 里，靠视口变换算命中与锚点）：优点是不侵占任何指针区域、`+` 可恒定屏幕尺寸；代价是要自己做 screen↔flow 坐标换算、订阅视口/位置保持锚点跟手、并把选中态常驻 `+` 一并搬走（两处 `+` 实现或跨组件协调），代码量约为采纳方案的 3 倍。触发带占位这一项在盘问中已被接受，故按 YAGNI 不上浮层。
2. **只用卡内区域做触发（不出卡）**：零副作用，但「从右侧空白靠过来提前出 `+`」这条盘问结论就没了，与 C4 冲突。

## 交互细则（实现约定）

- 触发带常驻渲染（不依赖 hover），但只在**本卡可派生**时才挂：`derivableKinds(kind).length > 0 || canDerive3d(asset)`，且跳过 `pending_` 占位卡（占位卡拿不到真实资产 id，派生无意义）。
- 指针类型为 `touch` 的移动不触发跟随（触摸没有 hover 语义，避免 `+` 粘在最后一次触摸点）。
- 退场用既有 `useExitTransition(open, 180)`：`closing` 期把偏移置 0（滑回中点）并叠 `.anim-fade-out`，到点卸载。
- 非选中态 `+` 进场用 `.anim-media-in`（既有 200ms 淡入）。
- 「+」的 `onClick` 继续 `stopPropagation` + `openAddMenu({ x: 按钮右缘+8, y: 按钮上缘, sourceId })`，**不改变选中态**。
- 媒体区门控统一写法：`nodrag`、`onMouseDown` 阻断、`onClick`/`onDoubleClick` 处理器一律在 `selected` 为真时才挂；视频的播放/放大按钮与音频播放器在非选中态**保留视觉**但整块 `pointer-events-none`（卡片仍读得懂「这是可播放的视频」，第一次点击先选中）。
