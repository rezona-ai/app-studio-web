# 画布交互五项打磨（2026-08-12）

## 目的

画布上五处交互当前是「功能已通、手感未磨」的状态。本轮不加新能力，只改交互形态与反馈：

1. 对齐从「常态强制」变成「用户可关的开关」，且对齐口径收窄到卡片边缘、辅助线不再突出难看的一段；
2. 资产列表面板不再拉满画布高度；
3. 资产细节从「右侧常驻面板 + 工具条开关」变成「右键贴卡浮窗，随卡移动」；
4. 成组不再等接口回来才出现；
5. 分组框可以从内部空白处直接拖动，卡片移入/移出分组有明确高亮。

## 约束与决策

### 1. 对齐开关（替换 spec 2026-08-04-canvas-align-guides 的常开语义）

- **开关管两套吸附**：网格吸附（`snapToGrid` + `SNAP_GRID`）与卡片边缘对齐（`applyDragSnap` + 辅助线）由同一个开关统辖。关闭 = 完全自由拖拽（等价于恒久按住 Alt）。
- **默认开、持久化**：默认值沿用今天的行为（开）；关掉等于连网格粒度都放弃，不适合做默认。开合是用户偏好 → 进 `partialize`，与 `listOpen` 同一级（我自行判定，未在盘问中确认）。
- Alt 临时绕过**保留**：开关是长期偏好，Alt 是单次手势内的临时豁免，两者不互斥。
- 开关入口在底部工具条，与 minimap / 列表 / 工具切换同款 `IconButton`（`raised-active` 表示开）。
- **对齐口径收窄到边缘**：`xEdges` / `yEdges` 去掉中线特征值，只留起始边与结束边。跨值组合（left↔right）仍然覆盖「相邻贴合」，故「卡与卡贴边」这条主用例不丢。中心对中心的对齐能力被有意放弃 —— 用户明确只要边缘。
- **辅助线不外延**：`GUIDE_PAD` 从 12 改为 0，线的两端**正好**落在参与对齐那批卡的最外缘上，不再从卡边突出一段。
- 虚线样式改为显式点划节奏（4px 实 / 4px 空），不再依赖浏览器对 `border-dashed` 的默认解释 —— 后者的段长随线宽变化，`1/zoom` 补偿下不同缩放比会画出粗细不一、疏密不一的线。

### 2. 资产列表面板高度

- **按内容自适应、夹在 240～520px、垂直居中**。卡少时面板就短，不留大片空白；超过 520px 内部滚动。
- 可用高度不足（`top-16` 到 `bottom-24` 之间的空间小于 240px）时跟着变短，仍然不遮挡顶部搜索栏与底部工具条。
- 左侧留边（`left-5`）与宽度可拖拽（`listWidth`）不变。

### 3. 资产细节：右键贴卡浮窗

- **删掉**工具条上的资产详情开关按钮、`AssetInspector` 右侧常驻面板、以及 `inspectorOpen` 这个状态（含其持久化）。
- **单选右键 → 一个浮窗，上下两段**：上段是今天 `SingleAsset` 的全部内容（名称 / 类型 / 提示词 / 模型参数 / 上下游血缘 / 再生成），下段是今天 `ContextMenu` 单选那几项动作（@用作引用 / 重命名 / 下载 / 删除）。`ContextMenu` 与 `AssetInspector` 两个入口收敛成一个。
- **多选右键维持现状**：仍是今天的光标菜单（圈成一组 / 批量引用 / 批量下载 / 批量重试 / 删除 N 个），定位在光标处、不跟随移动，**不展示卡片细节**。两种形态共用同一套菜单项渲染。
- **锚点与跟随**：浮窗贴在被右键那张卡的一侧，卡片移动（拖拽 / 方向键微调 / 一键整理 / 拖框带动成员）时浮窗跟着走；画布平移缩放时同样跟随。
- **尺寸恒定**：浮窗是屏幕像素口径（宽度、字号与今天的属性面板一致），只把锚点从画布坐标换算成屏幕坐标。缩到 10% 时文字仍可读。
- 贴边夹取：浮窗优先贴卡片右侧，右侧空间不够时翻到左侧；上下同样夹进视口（留 8–12px 边距），与既有菜单/Tooltip 的夹取口径一致。
- 卡片被删除 / 被筛选隐藏 / 项目切换时浮窗关闭；点击空白、Esc、右键另一张卡都关闭。
- **列表面板行右键**：走同一个浮窗组件，但锚点用**光标位置**且不跟随 —— 列表里的卡可能在视口外，强行把视口拽过去会打断「一边查一边定位」（我自行判定）。

### 4. 成组立即生效

- 「圈成一组」点下去**立刻**在画布上出现框并把选中卡收进去，不等 `POST /canvas/groups` 返回。
- 乐观期用临时 id（与卡片 `pending_` 占位符同一套思路的前缀），真实 `group_id` 到位后重映射：框自身、成员 `groupId`、乐观期内堆积的回写全部换成真 id。
- **乐观期可操作**：改名 / 缩放 / 移动 / 往里拖卡在乐观期全部本地生效；需要落库的回写排到真实 id 到位之后，按「最终状态一次性回写」发出（不重放中间态）。
- 创建失败：回滚 —— 框消失、成员归属恢复，弹 Toast「成组失败」。这是唯一的失败提醒（用户明确要求「仅在接口调用失败的情况下提醒」）。
- 撤销栈语义不变（本轮不给「创建分组」加撤销格）。

### 5. 分组框拖动与移入/移出高亮

- **框内空白左键拖 = 拖整个分组**。这条推翻 spec 2026-08-05-canvas-groups 决策 2（框体恒 `pointer-events: none`）—— 该决策为的是保住框内的橡皮筋框选。
- **框内框选改为 ⌥ + 拖**。⌥ 在框内的语义因此变成「框选而非拖框」；⌥ 在卡片上仍是「临时绕过吸附」，两者作用对象不同、不冲突。
- 标题条与八个缩放把手的现有语义不变（标题条仍可拖、双击改名、把手仍缩放）。框内**卡片上**按下仍然是拖卡，不会误拖整框。
- **移入高亮**：拖卡期间实时按中心点判定命中框，命中框显示 drop-target 态（描边转品牌青 + 底色加深）。
- **移出高亮**：被拖的卡原属某框、而当前命中框不是它时，原框显示「将移出」态（描边转虚线并减淡）。
- 高亮是纯瞬态视觉，不进 store 持久化切片；松手即清。

## 成功标准

1. 关掉对齐开关后拖卡：无辅助线、落点不再被网格量化；重开后恢复。刷新页面开关状态保留。
2. 拖一张卡贴另一张卡的左边缘：吸附命中、辅助线两端正好落在两张卡的最外缘（不突出）；把两张卡的**中心**对齐时不再有吸附与辅助线。
3. 3 张卡时列表面板明显变短且垂直居中；40 张卡时面板高 520px、内部滚动；两种情况都不压顶部搜索栏与底部工具条。
4. 工具条上不再有资产详情按钮，右侧不再有常驻面板；右键一张卡出现贴卡浮窗，含细节与四项动作；拖动该卡浮窗跟着走；缩放到 10% 与 200% 浮窗尺寸不变。
5. 右键多选：仍是光标处菜单、无细节区。
6. 断网时圈成一组：框立刻出现，随后消失并弹「成组失败」；正常网络下框立刻出现且改名/缩放不丢。
7. 框内空白左键拖动整框（成员跟随）；⌥ + 拖在框内框选。
8. 拖一张散卡进框：框高亮；把成员拖出去：原框显示将移出态；松手后成员数与归属正确。

## 实现期发现（自评抓到、已修）

三条都是「乐观化 / 换宿主」这两个动作带出来的边缘路径，各自有承重测试：

1. **临时框 id 的别名**（`groupIdAlias`）：圈成一组后立刻拖框，松手时 React Flow 手里那份节点还是临时 id（拖拽期节点同步被 `isDraggingRef` 挡着），`groups.find` 落空 ⟹ 本地与回写双双静默丢失、框在下一次同步时弹回原位。按 gid 找框的入口（本地 patch / 几何 / 移动 / 删除 / 待删 id / 撤销恢复 / 归组）与回写闸门 `withRealGroupId` 统一过别名。其中 `assignGroup` 入口那层没有独立测试（变异掉它无人变红）：它是**归一化**而非分支 —— 去掉后闸门仍能解别名、递归也在同一同步帧纠正本地值，但中间会多出一次「`groupId` 指向已不存在的框」的状态发布，只是当前恰好没有同步消费者（全仓无 `useStore.subscribe`，React 同帧只渲染最终值）。不赌这个易变前提，保留归一化。
2. **后台刷画布抹掉临时框**：`run.finished` 之后的 `loadCanvas` 整表替换 `groups`，服务端还不知道这个框；而成员的 `groupId` 因 `preserveFrontendOwned` 留着 ⟹ 框凭空消失 + 一批悬空归属。按「在飞占位卡」同款豁免带过整表替换。
3. **浮窗与生成表单同层**：重试路由到 `editForm` 时开生成表单，表单内容与贴卡浮窗同为 `fixed z-50`，谁上谁下只由 DOM 序决定 —— 正文原先长在 `z-10` 的常驻面板里、被模态遮罩自然盖住，搬进浮窗后这层保护没了。改为点「再生成」先收浮窗。

另有两条**已知代价**（非缺陷，取舍所致），都源自「框体开始吃指针」，两条都要求命中 `.react-flow__pane`：

- 框内空白**双击**不再能开「新增资产」菜单；
- 框内空白**单击**不再清空选中（`onPaneClick` 不触发）。

两者都能用 ⌥ + 手势绕过，已写进 `GroupNode` 的头注释。

### 终审处置（合并前）

子代理终审报 2 Critical / 4 Important / 7 Minor，逐条对着代码库验证后：C1 C2 I1 I2 I3 M1 M2 M3 M4 M5 M6 M7 全部采纳并修复（各有承重测试，其中对齐开关接线、别名三处入口都做了变异验证：改错必红）。一处技术性异议提了、也被复核推翻了一半：我原以为 `assignGroup` 入口那层别名「无法单独观测」，故按「不留测不出的分支」删掉。复核用同步订阅者探针实测到它**是可观测的**（两次真实 `set` 发布，中间那发里 `groupId` 指向已不存在的框），只是当前无消费者。理由既然不成立，就按更保守的一支把归一化加回去，并把真实理由写进注释。

第二轮增量复核另报 5 条 Minor（M-a…M-e），全部采纳：M-a 我那条「关掉对齐不产生辅助线」的用例是**空转**的（假 ReactFlow 没灌节点 → 候选集恒空；且辅助线活在 `ViewportPortal` 里，桩掉 ReactFlow 后压根不渲染），判别点改为直接记录 `applyDragSnap` 收到的 `bypass`，变异必红；M-d 建框主路径的归属回写失败同样回滚不掉（与 M5 同病，漏在主路径）；M-e 乐观期删框后撤销时服务端从未收到成员归属，需补发一次；M-b `CanvasTool` 手抄的联合类型下沉到 `store/types`；M-c `beforeEach` 恢复重置以免「进持久化切片」变成顺序依赖。

## 不做

- 不给「创建分组」加撤销栈条目。
- 不做浮窗内的批量细节视图（多选无细节）。
- 不改分组框的后端契约与几何模型（几何仍是归属真相）。
- 不补列表面板的键盘导航（沿用 2026-08-04-canvas-list-view 的「未验到」记录）。
