# 国际化(i18n)设计稿

- 日期:2026-06-26
- 目标:为分站接入多语言能力,支持 **英文 en / 中文 zh / 越南语 vi / 西班牙语 es**。

## 背景与现状

- 项目当前**无任何 i18n 设施**:无 i18n 库、无 locale 目录、`<html lang>` 非动态绑定语言。
- 用户可见文案**硬编码**(以中文为主、个别英文如 `Loading workspace…`),散落在 ~84 个组件的 JSX 文本、`aria-label`/`title`/`placeholder`/`alt`、`<option>` 文本、按钮文案、前端自造的 Toast/错误字面量里。
- **本应用是分站**:主题与语言**不自管**,由主站经 `localStorage['taluna-config']`(含 `theme`/`lang`)下发——首屏由 `layout.tsx` 防白闪内联脚本读取并设 `<html data-theme>`/`<html lang>`,运行期由主站经 `postMessage` 下发、`useHostConfig` 实时应用(分站**不回写** localStorage)。
- 主题的读取范式:`useIsDark` 用 `useSyncExternalStore` + `MutationObserver` 监听 `<html data-theme>`,SSR/首帧取确定性 server snapshot(深色),挂载后切真实值,**不报水合不匹配**。i18n 将**对齐这套范式**。
- 错误模型:`PgcError { code: string; message: string; status }` →(`guard` 捕获)→ store `lastError: ToastMessage { code; message; kind? }` → `Toast` 组件渲染 `message`。

## 决策摘要(已与用户确认)

| 维度 | 决策 |
|---|---|
| 覆盖范围 | 前端 UI chrome **全翻译** + 后端 error **按 code 兜底映射**(无映射回退后端原文);LLM 对话内容**不译** |
| 技术选型 | **react-i18next**(自带插值/复数/语言切换事件) |
| locale 真相源 | **纯主站驱动**,从 `<html lang>` 读取,**不自建切换器**、**不入 persist store** |
| 回退语言 | **en**(i18next `fallbackLng`,词条须完整) |
| 译文产出 | 由 Claude 直接产出 en/vi/es 全量词条(AI 翻译水平,后续可人工校对) |

## 架构

### 模块结构(新增 `src/i18n/`)

```
src/i18n/
├── config.ts        # 纯逻辑:支持列表 / 回退 / 归一
├── index.ts         # i18next 单例 init
├── locales/
│   ├── en.ts        # canonical 源形状
│   ├── zh.ts        # : Messages
│   ├── vi.ts        # : Messages
│   └── es.ts        # : Messages
└── errors.ts        # 后端 error code → i18n key 映射 + 解析 helper
```

#### `config.ts`(纯函数,易测,无副作用)

```ts
export const SUPPORTED = ['en', 'zh', 'vi', 'es'] as const;
export type Locale = (typeof SUPPORTED)[number];
export const FALLBACK: Locale = 'en';

// 归一:小写 → 取主子标签(zh-CN/zh_CN → zh)→ 命中支持列表则返回,否则回退 en。
// 输入可为 undefined / 任意字符串(主站下发值不可信),恒返回合法 Locale。
export function normalizeLocale(input?: string | null): Locale;
```

#### `index.ts`(i18next 单例)

- `i18n.use(initReactI18next).init({ resources, lng, fallbackLng: 'en', interpolation: { escapeValue: false }, returnNull: false })`。
- `resources` = 静态打包四套词典(总量小,无需 HTTP 懒加载,亦规避 basePath `loadPath` 复杂度)。
- **初始 `lng` 确定性取 `'en'`**(SSR 与首帧一致),真实语言由挂载后的 effect 切换(见「水合策略」)。
- 默认单一命名空间(`translation`)。

#### `locales/*.ts`(类型安全的词典)

- `en.ts` 导出 canonical 对象;`type Messages = typeof en`。
- `zh.ts`/`vi.ts`/`es.ts` 标注 `: Messages` —— **缺 key 编译期 `tsc` 直接报错**,这是在 react-i18next 之上补回的「编译期 key 校验」。
- `zh.ts` 的值 = **逐字复制现有硬编码中文**(保证现有体验零变化、且现有组件测试断言不破——见「测试」)。
- key 组织:**单命名空间 + 按区域分组的点号 key**,镜像组件目录:`common.* / chat.* / canvas.* / preview.* / errors.*`。
- 插值:`第 ${page+1} 题,共 ${n} 题` → `t('chat.question.progress', { cur, total })`,词条 `第 {{cur}} 题,共 {{total}} 题`;天然需要复数的场景(如版本计数)用 i18next 复数后缀(`_one`/`_other`),其余不强加复数。

#### `errors.ts`

```ts
// 后端 error code → i18n key。只收录已知 code;未知 code 不在表中,回退后端原 message。
export const ERROR_KEYS: Record<string, string>;
// 命中且词条存在 → 译文;否则回退 fallbackMessage(后端原文 / 现行行为)。
export function resolveErrorMessage(code: string, fallbackMessage: string, t: TFunction): string;
```

### locale 真相源与接线

- **真相源 = `<html lang>`**,完全由主站驱动:首屏防白闪脚本设、运行期 `useHostConfig` 经 postMessage 更新。**这两处已存在,本设计不改其来源**,只新增「把语言同步给 i18next」这一步。
- `useHostConfig` 在已设 `document.documentElement.lang` 之后,追加 `i18n.changeLanguage(normalizeLocale(config.lang))`。
- 新增一个极小的 client 组件 `I18nProvider`(包裹根路由 `src/app/page.tsx` 的 `<Workspace />`;入口已从 `src/app/studio/page.tsx` 迁至根路由):`import '@/i18n'` 触发 init,挂载时一次性 `i18n.changeLanguage(normalizeLocale(document.documentElement.lang))`,把 SSR 的 `en` 对齐到内联脚本已设好的真实语言。
- react-i18next 的 `useTranslation()` 订阅 i18n `languageChanged` 事件,语言变化时**自动重渲染**所有用 `t()` 的组件——无需把 locale 放进 store。

### 水合策略(对齐 `useIsDark`)

- SSR 与客户端首帧:i18n `lng === 'en'`(确定性),`booting` 期只渲染 `LoadingScreen`,首帧仅其一个文案节点。
- 挂载后 `I18nProvider` 的 effect `changeLanguage(真实语言)` → 重渲到真实语言。
- 因为服务端与客户端首帧渲染完全一致(都 en),**不产生水合不匹配**;非 en 用户首帧到真实语言的「闪一下」仅作用于 loading 文案,可忽略。

### 后端错误本地化

- store 仍只存原始 `{ code, message }`(不污染数据层、不臆造字段)。
- **在 `Toast` 组件渲染时本地化**:`resolveErrorMessage(lastError.code, lastError.message, t)`。命中映射用译文,否则回退后端原 `message`(`notice` 类同理)。
- 好处:语言切换时已显示的 Toast 自动重渲为新语言。

## 数据流

```
主站 ──taluna-config(lang)──▶ ① 防白闪脚本(首屏) / ② postMessage→useHostConfig(运行期)
                                          │ 设 <html lang> 并 i18n.changeLanguage(normalize(lang))
                                          ▼
                            i18next 单例(languageChanged 事件)
                                          ▼
组件 useTranslation()→t('…') ── 自动重渲 ──▶ ChatPanel / AssetCanvas / PreviewPanel / Toast …
                                          ▲
后端 PgcError{code,message} ──▶ store lastError ──▶ Toast: resolveErrorMessage(code,message,t)
```

## 错误处理与边界

- 主站下发非法 / 不支持 / 缺省 `lang`:`normalizeLocale` 恒回退 `en`,渲染不中断。
- 缺失词条:i18next `fallbackLng: 'en'` 兜底;`en` 须完整(类型 + 运行期一致性测试双保险)。
- `<html lang>` 沿用主站原值(可能是 `zh-CN` 等带 region 值,合法);归一仅用于**选词典**,不回写覆盖该属性。
- 非法 postMessage 帧:沿用 `useHostConfig` 现有 `try/catch` 跳过。

## 测试

- `normalizeLocale`:纯函数单测(各 region 变体、未知、空、大小写、下划线)。
- `resolveErrorMessage`:命中映射 / 未命中回退原文 / 词条缺失回退。
- **四套词典 key 集合一致性**运行期测试(以 `en` 为基准,断言 zh/vi/es key 集合相同)——与 TS 类型互为双保险。
- **测试语言固定为 `en`**:`vitest.setup.ts` `import` i18n 并 `i18n.changeLanguage('en')`。
  - 理由:**现有 UI 绝大多数文案本就是英文**,现有组件测试也几乎都按英文查询(`getByRole('button',{name:'Send'})`、`'Size'`、`'Generate'`、`'Copy link'`、`'Advanced settings'` 等)。`en` 词条 = 这些英文源串**逐字复制**,这批测试**原样通过**;若改用 zh 反而会让数十个测试挂掉。
  - 例外:**少数中文源文案**的测试(`AssetChip`/`ToolApprovalCard`/`QuestionCard`/`AttachmentBar`/`MessageSkeleton`/`ToolCard`)断言的是中文(如 `移除引用`/`批准`),在 `en` 下渲染为英文译值,需在对应区域任务里把断言改成英文译值(如 `Remove reference`/`Approve`)。
- 抽样组件测试在 `en` 下校验 `t()` 渲染结果与原英文文案一致。

## 实施顺序(供后续 plan 细化)

1. 装依赖(`i18next` + `react-i18next`);scaffold `src/i18n/`(config + init + 空词典骨架 + `I18nProvider` 接线 + `useHostConfig` 同步)+ 纯函数测试;`vitest.setup` 切 en。
2. 按区域抽取文案(`common`/`ui` → `chat` → `canvas` → `preview`),逐区域替换字面量为 `t()` 并补齐四套词典。
3. 后端 error 映射 + `Toast` 本地化。
4. 验证:`tsc` / `lint` / `test` / `build` 全绿;手动切 `<html lang>`(en/zh/vi/es + 非法值)肉眼核对。

## 不在范围内

- LLM 对话(agent 回复)内容的翻译。
- `layout.tsx` `metadata`(浏览器标签标题/描述,主站层面,SSR 无请求级 locale)。
- 自建应用内语言切换器。
- 数字 / 日期 / 货币的区域格式化(当前 UI 无此需求;如需另立 spec)。
