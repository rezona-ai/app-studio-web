# 一键整理纳入引用边 · 设计稿（v2：DAG 布局）

日期：2026-07-04（v2 取代同日 v1「布局父」方案）

## 背景与目标

多引用连线落地后，画布同时存在**一对多**（parentId 派生树）与**多对一**（多引用 → 一个生成物）两种关系。v1 只挑 `refIds` 首个有效引用作布局父，其余引用仍是散根——实际效果与旧货架铺放肉眼无差（验证于真实项目 368：ref1←gen 树排后，ref2 恰好铺同行，画面仍是「3 个共行」）。

v2 目标：整理布局完整表达 DAG——多个被引用资产竖排在左列，生成卡在右列对它们**垂直居中**；引用资产自带子树时**整体参与**分组排列。

## 布局算法（`tidyLayout` 森林 → 分量化 DAG）

### 边与分组

- 布局边集 = `parentId` 边 ∪ `refIds` 边（方向均为 被引用者 → 生成物）；有效边 = 两端在集合内且非自指。
- 无向**连通分量**取代「树盒」作为货架铺放单元：引用把多棵树连起来时整体成一个分量。
- 分带（kindOrder）按分量内最左上根（按当前位置排序的首个无入边节点；全环分量则取最左上节点）的 kind 归带。

### 列（x）：最长路径分层

- 节点列 = max(所有入边父的列) + 1；无入边节点列 0。
- 列宽仍按该分量各列真实最大宽（`width ?? CARD_W`）累计 + `GAP_X`。
- 防环：分层用 DFS/迭代计算时忽略构成环的回边（沿用既有 visited 思想），保证终止；环上节点按首次可达深度落列。

### 行（y）：两遍法

1. **主父生成树 + Reingold–Tilford**：每分量加虚拟超根，分量内所有无入边根作其子（按当前位置排序）；每节点取首条入边为主父（parentId 优先于 refIds，refIds 按数组序），跑现有变高 RT 得初始 y——根竖排、子树相对定位、兄弟按真实底边堆叠全部保留。
2. **多父居中修正**：按列从左到右一遍，把入边 ≥2 的节点 y 调到其所有父的 y 中心（按各自高度取中心对齐）；同列节点冲突时按 y 序依次下推避让（保持列内 `GAP_Y` 不重叠），不追求最优交叉数。

### 退化与回归面

- 无 ref 边的画布：每个分量即原来的一棵树，虚拟超根下单根、无多父修正 → 结果与 v1/v0 树形一致（既有测试锁定）。
- 货架铺放（分量包围盒从左到右、超 `MAX_ROW_WIDTH` 换行）、锚点（全卡 min x,y）、网格吸附、取整均不变。
- `selectCanvasEdges`、位置归前端所有原则不变。

## 接口

`tidyLayout(nodes: TidyNode[], kindOrder?: string[])` 签名不变；`TidyNode.refIds?: string[]` 已存在（v1）。调用方 `tidyCanvas` 已传 `refIds`，无需改动。

## 测试

`src/lib/card-layout.test.ts`：

- 多对一：2 个裸引用 + 1 生成卡 → 引用竖排列 0，生成卡列 1 且 y 居中于两引用带中心；
- 引用带子树：ref2 另有 parentId 子链 → 整个子树与 ref1、gen 同分量，gen 列 = max(父列)+1；
- 一对多不回归：纯 parentId 树输出与 v1 逐点一致（用既有用例锁）；
- 混合：父子 + 引用交织的分量整体铺放，不拆散；
- 互指环：忽略回边不死循环，两节点各落位一次；
- v1 既有用例中与「首个引用为布局父」绑定的断言按 v2 行为更新（多引用场景 y 居中取代同 y）。
