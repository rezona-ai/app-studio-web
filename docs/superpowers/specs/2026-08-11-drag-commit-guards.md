# 拖拽收口的三道门：没动过就什么都别写

> 状态：设计稿 · 2026-08-11
> 分支：`fix/drag-commit-guards`（终审整改 C 批 / 共四批；A 已合并 `49be06b2`，B 待合并）
> 来源：2026-08-10 全量终审，`rv-canvas-groups` 与 `rv-align-guides` 各自撞到，均已由我对着 HEAD 逐行核实
> 关联：`2026-08-04-canvas-align-guides.md`（引入吸附）、`2026-08-05-canvas-groups.md`（引入分组框）、
> `2026-08-07-undo-and-overlay-guards.md`（撤销带归属快照）

## 目的

三条缺陷共用一个成因：**`onNodeDragStop` / `handleNodesChange` 这条收口链上，
「这次到底动没动」这个判据只用来挡撤销栈，没用来挡真正的写操作**。
于是「什么都没做」的操作照样改数据、照样发请求。

| # | 用户做的事 | 期望 | 实际 |
|---|---|---|---|
| 1 | 拖一张卡贴到邻卡吸住（出青线）→ 继续拖到空白处（青线消失、卡回网格）→ 松手 | 落在网格位 | 松手瞬间**跳走 ≤ 阈值/zoom**，坐标不再是 10 的倍数 |
| 1′ | 吸住后按住 Alt 想逃出吸附 → 松手 | 逃出去 | 松手被**补回**刚才那个偏移 |
| 2 | 拖框把框搬到一张散卡上（spec 明确规定这张卡不入组）→ **左键点一下这张卡** | 只是选中 | 它的 `group_id` 被写进后端、框成员 +1，**⌘Z 撤不回** |
| 3 | 点「一键整理」→ 再点一次（布局确定、零位移） | 什么都不发生 | 入了一条**空**撤销条目，第一次 ⌘Z 只弹提示、卡片不动 |

## 现状核实（HEAD 实读）

| 事实 | 位置 |
|---|---|
| 松手帧无条件把 `lastDeltaRef` 加到坐标上，然后清零 | `AssetCanvas.tsx:637-641`（`applyDropOffset`） |
| 只有「命中过」才更新 `lastDeltaRef` | `AssetCanvas.tsx:654` |
| `applyDragSnap` 对**三种**不同情况返回同一形状（`dx=dy=0, guides=[]`）：Alt 绕过 / 本帧无拖拽变更 / 有变更但没命中 | `align-guides.ts:154`、`:156`、`:163` |
| ⟹ 调用方无法区分「这帧没吸上」与「这帧压根没拖」，陈旧 delta 被留住 | 上述两处的组合 |
| `groupChanges` 的**计算、本地应用、批量回写**都在 `if (moved)` **之外**，只有 `pushUndo` 在门内 | `AssetCanvas.tsx:686-694` / `709-718` vs `701-707` |
| 零位移点击确实会走到这里（该文件自己的注释承认） | `AssetCanvas.tsx:695` |
| `tidyCanvas` 在**算 layout 之前**就入栈 | `actions.ts:1710-1718`（`moved` 在 `:1725` 之后才算出来） |
| 对照：拖动与方向键微调两条路径都有 `moved` 守卫 | `AssetCanvas.tsx:696-700` / `:783-786` |

## 约束

- **C1 「动没动」是写操作的前置条件，不只是撤销栈的**。三处都按这条改：没位移就不写本地、
  不发请求、不入栈。
- **C2 `applyDragSnap` 要能回报「本帧是否处理了拖拽变更」**（`handled` 或返回 `dragged.length`）。
  这是修 #1 的关键：调用方据此决定「该不该把 delta 写回（含写回 `{0,0}`）」，
  而不是靠「有没有命中」间接推断。Alt 绕过那条同理 —— 它也是「处理过这帧」。
- **C3 不改吸附几何本身**：`snapToRects` / 阈值 / 六线判定一律不动，本轮只修状态承接。
- **C4 分组归属仍按「几何是真相」**，只是**重判的时机**收窄到「真的拖了」。
  零位移点击不重判 —— 它没有改变几何，没有任何理由改变归属。

## 方案

1. `align-guides.ts`：`applyDragSnap` 返回值加 `handled: boolean`（`dragged.length > 0`；`bypass` 时也算 handled，
   因为那一帧确实是拖拽帧）。`AssetCanvas.tsx:654` 改成 `if (r.handled) lastDeltaRef.current = { dx: r.dx, dy: r.dy };`。
2. `AssetCanvas.tsx`：把 `groupChanges` 的本地应用与 `persistAssetPositions` 一并挪进 `if (moved)`。
   `setAssetPositions` 也进门（零位移时它写的是同一份坐标，纯噪声）。
3. `actions.ts` `tidyCanvas`：先算 `layout` 与 `moved`，`moved.length > 0` 才 `pushUndoEntry`。

## 成功标准

1. 吸附命中后拖离到空白处再松手：落点等于松手前所见，且是 `SNAP_GRID` 的倍数。
2. 吸附命中后按住 Alt 拖离再松手：同上，不被补回偏移。
3. 吸附命中后**直接**松手：仍精确落在对齐线上（既有行为不回归）。
4. 拖框覆盖一张散卡后，左键点该卡：`group_id` 不变、不发 PATCH、撤销栈不增长。
5. 真的把卡拖进/拖出框：归属照旧改、照旧回写、照旧可 ⌘Z（既有行为不回归）。
6. 连点两次「一键整理」：第二次不入撤销栈、不发请求。
7. 首次「一键整理」照旧可撤销（既有行为不回归）。

## 增量评审处置（2026-08-11，基于 `d2cb26b7~1..97f967d1`）

### 那节「已知缺口」已作废 —— 我的结论被驳回了

T2 落地时我实测出「`AssetCanvas.tsx:655` 那行接线没有任何测试锁住」（删掉或退回旧判据，
34 个画布测试文件全绿），并把它记成已知缺口，理由是「jsdom 里容器 rect 全 0 ⟹ 候选集为空，
要锁得把视口与容器尺寸一起桩掉，成本与本条缺陷的体量不成比例」。

**评审驳回了后半句，并给出了证据**：rect 全 0 属实，但只要补一个 `getBoundingClientRect` 桩
（返回 1200×800）就够——夹具主体本来就在。它实跑拿到了变异下的双红。

处置：**采纳，已补锁**（`AssetCanvas.dragstop.test.tsx` 的「松手帧不承接失效偏移（接线）」三条）。
变异复验：退回旧判据 → 2 红；整行删掉 → 1 红。成功标准 1、2、3 从「部分」变成「已钉住」。

教训写在这里：**「锁不上」要拿证据说，不能拿成本估算说。** 我那句「成本不成比例」是估算，
而估算错了 —— 真实增量是一个 4 行的桩加三帧喂入。
