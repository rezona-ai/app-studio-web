# 画布任务可见性：几个在跑 · 已等多久

> 状态：设计稿 · 2026-08-04
> 关联：P2 第四组（末组）。已完成：可靠性、输入与浏览、键盘手感。
> 卡后端的不做：**取消生成任务**、**生成前预估消耗**。**2026-08-05 后端答复更新**：取消生成
> **后端明确不做**（上游 provider 无 cancel API）；估价与分组框端点均已提供，各自单独立项。

## 目的

**视频 / 3D 是分钟级、要花钱的操作，而 UI 上只有一个转圈。**

现状：

- `GenTask`（`types.ts:148`）已经存着 `startedAt` / `kind` / `taskId` / `fails`，但**没有任何地方读它来给用户看**。
- 生成中的卡只有 `GeneratingPlaceholder` 的微光骨架，不显示已等多久。
- 全仓库没有任务列表入口：「到底还有几个在跑」无从知晓 —— 尤其 agent 在对话里提交的任务，
  卡可能落在视口外（上一组刚做的「N 个新资产」角标只覆盖了**已完成**的新卡）。
- 兜底机制对用户不可见：超过 `DEADLINE_MS = 10 分钟`（`actions.ts:93`）强制判失败、连续 5 次轮询失败也判失败。
  用户视角是「转了十分钟，忽然变成一张失败卡」。

## 约束

1. **入口按需出现**：无在跑任务时不占位；有任务时在画布上出现「生成中 N」药丸，点开列出每个任务的类型与已等时长，
   点条目飞到那张卡。与上一组「N 个新资产」角标同一视觉语汇。
2. **卡上时长超过 10 秒才显示**：图像 / 音频常常 3 秒就回来了，计时器一闪而过是纯噪声；
   视频 / 3D 是分钟级，10 秒后再出数字，正好只在「开始让人心里没底」时出现。
3. **超过 5 分钟转警示色**：10 分钟是既有的强制判失败线。到点才突然变失败卡太突兀，
   过半时先把计时文字转 `--color-warning`、面板里标「较慢」。
4. **不做取消**：后端没有取消端点。UI 上**不放**假的取消按钮 —— 宁可没有，也不要点了没反应。
5. **计时只在有任务时走**：秒级 tick 用一个定时器统一驱动，无任务时不注册，不做每卡一个计时器。
6. **纯逻辑下沉**：时长格式化、阈值判定、任务行的派生都是纯函数进 `lib/`；DOM 与计时器留在组件。
7. **瞬态不落盘**：tick 只是重渲染的驱动，不进 store、不进 persist（`genTasks` 本身已有既定的持久化口径，不动它）。
8. UI 复用既有令牌与 `.anim-pop-in`；药丸沿用 `NewAssetsBadge` 的形制，不新增按钮种类、不自造浮层样式。

## 成功标准

1. 无在跑任务时，画布上没有任何任务入口。
2. 提交一个视频 / 3D 生成 → 出现「生成中 1」药丸；再提交一个 → 变「生成中 2」。
3. 点药丸展开列表：每行显示类型图标 + 已等时长（`m:ss`），点某行视口飞到那张卡。
4. 卡上前 10 秒不显示时长；第 11 秒起显示并逐秒递增。
5. 超过 5 分钟：卡上与面板里的时长转警示色，面板行标注「较慢」。
6. 任务结束（成功 / 失败）→ 该行消失；全部结束 → 药丸消失。
7. 切项目 → 药丸只反映当前项目的任务（`genTasks` 本就按项目隔离）。
8. 无在跑任务时不存在秒级定时器（性能：空闲画布不该每秒重渲）。
9. 刷新后仍在跑的任务（`restoreGenTasks` 恢复的）同样计入药丸与列表，时长从原 `startedAt` 起算。

药丸位置：画布**右上**（`absolute right-5 top-16`）—— 左上是列表面板、正上方居中是「N 个新资产」角标、
底部中间是工具条、右下是筛选按钮，右上是唯一空位；展开列表向下生长，超出时由 `clampPopover` 兜住。

## 明确不做

- **取消任务**：见约束 4。2026-08-05 起记为**后端明确不做**（上游无 cancel API），不再是「等端点」。
- **预计剩余时间**：后端不返回进度，凭历史均值瞎猜会比不显示更糟。
- **进度条**：同上，没有真实进度就不画进度条。
- **失败任务留在列表里**：失败已由失败卡（含原因 + 重试入口）承担，列表只管「在跑的」。
- **跨项目的全局任务中心**：`genTasks` 按项目隔离是既定语义，本轮不动。

## 真机验收（2026-08-04，dev :3010，项目 Star Whisper-v82，33 张卡）

**没跑真实生成**：完整链路要花积分等分钟级，本轮按计划改用「直接驱动 `genTasks` + 把两张真实卡置 generating 态」
来验 UI —— 与真实链路是同一份状态（`genTasks` 的 `startedAt/kind/itemId` 就是轮询登记时写进去的那些字段）。
真实生成那一跳（提交 → 登记任务 → 药丸出现）未验，见「未验到的」。

已验：

1. **空闲无入口、无定时器**：无任务时画布上没有任务药丸；包一层 `window.setInterval` 观察 2.5 秒，
   **新注册的定时器为 0**（成功标准 8）。
2. **药丸计数**：塞两条任务 → `Generating 2`；只剩一条 → `Generating 1`。位置落在画布列右上（距画布右边缘 20px、顶部 64px）。
3. **列表按等最久在最上**：`cine_2_transit 6:11 Slow`（警示色）在上，`cine_1_departure 0:23` 在下。
4. **时长在走**：同一任务两次读数 `0:13 → 0:23 → 0:50`，逐秒递增。
5. **卡上时长**：`cine_1_departure | Video | 0:50`、`cine_2_transit | Video | 6:38`，后者的 span 带 `--color-warning`。
6. **不足 10 秒不显示**：把任务的 `startedAt` 设成 5 秒前 → 卡面只有 `cine_1_departure | Video`，无时长。
7. **点条目飞过去**：视口 transform 变化，列表随即收起。
8. **任务结束**：`genTasks` 清空 → 药丸消失；之后再观察 2.2 秒，**新定时器为 0**（单例 tick 被回收）。
9. **收尾**：重载后 33 张卡全 `ready`、无任务、四行布局未变（假任务只改了内存态，`genTasksByProject` 未被写入）。

**未验到的**：

- **真实生成的那一跳**：提交视频/3D → 服务端返回 task → `commitGenTasks` 登记 → 药丸出现。
  这段需要真实生成（消耗积分、分钟级），本轮没跑。中间环节由既有测试覆盖，但「端到端第一次出现药丸」没验。
- **`restoreGenTasks` 恢复的任务**（成功标准 9 的刷新场景）：同样需要一个真在跑的任务才能造出来。
