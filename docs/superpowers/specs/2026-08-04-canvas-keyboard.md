# 画布键盘手感：⌘A 全选 · 方向键微调真正落库

> 状态：设计稿 · 2026-08-04
> 关联：P2 第三组。已完成：可靠性（`2026-08-04-canvas-persist-reliability.md`）、输入与浏览（`2026-08-04-canvas-input-browse.md`）。
> 同期未做：P2 的「任务可见性」；「取消生成 / 预估消耗」等后端端点
> （2026-08-05 更新：取消**后端明确不做**，估价端点已提供）；血缘手动连线（产品决策待议）。

## 目的

原初判里这一组写的是「无 ⌘A 全选，无方向键切换选中，无空格临时平移」。动工前逐条真机核实，结论与判断不同：

| 能力 | 真实现状 |
|---|---|
| 空格临时平移 | **已经能用**。RF 默认 `panActivationKeyCode = 'Space'`，本项目没覆盖它；真机实测按住空格拖 pane，视口精确平移了拖拽量（+150/+100），按住期间 pane 挂上 `draggable` |
| ⌘ 点击多选 | **已经能用**。RF 默认 `multiSelectionKeyCode = Meta` |
| Shift 框选 | **已经能用**（另有本项目的 `selectionOnDrag`） |
| ⌘A 全选 | **确实缺**。按下无任何反应（选中数不变） |
| 方向键 | **是个假功能** —— 见下 |

### 方向键微调不落库（静默数据丢失）

RF 的 a11y（`disableKeyboardA11y` 默认 false）已把方向键绑成「移动选中节点」，一下一个网格、`Shift` ×4。
但它走的是 `moveSelectedNodes` → 直接改 RF 内部状态，**绕过 `onNodeDragStop`**，所以本项目的
`persistDraggedNodes` 从不触发。

真机实测：选中 `amb_ship_engine` 按一次 `→`，DOM 的 transform 变成 `120,260`，而 store 里仍是 `110,260`；
刷新后卡回到 110。也就是说位移只活在 RF 内部，**不落库、不进撤销栈，store 任何一次 sync 都会把它冲掉**。

这与上一组刚做完的「坐标回写不再静默」是同一类问题的另一条漏口：那组修的是「写失败不告知」，
这里是「压根没写」。

## 约束

1. **方向键保留「移动」语义**，不改成切换选中：RF 已有该 a11y 语义（屏幕阅读器依赖它）、`Shift` 加速与网格吸附天然对齐；
   而自由布局画布上「右边那张是哪张」定义含糊。要做的是把它**接上落库与撤销**。
2. **连续微调合并为一次撤销**：停手 500ms 内的连按算一步（记录第一下之前的坐标）。否则撤销栈（上限 20）
   一按方向键就被微步刷空，把之前的操作全挤出去。
3. **落库复用既有通道**：`persistAssetPositions`（限流 6 + 同坐标合并 + 退避重试 + 聚合 Toast），不新增写路径。
4. **⌘A 选「当前视口内看得见」的卡**，且不含被类型筛选隐藏的 —— 两个条件都要。
   只看类型筛选会把屏外的卡也选进来（与「可见」的直觉不符，真机反馈后改成这条）；
   只看视口会在「筛掉音频」时把隐藏的音频卡选中，紧接着的批量删除就误伤。
   ⚠️ 这与 ⌘A 的业界惯例（Figma 等：选中全部对象、不看视口）不同，是本项目的有意选择。
5. **焦点在输入类元素时全部放行**：⌘A 在输入框里是「全选文本」，方向键是移动光标。沿用既有
   `isEditableTarget` 口径（与删除键、撤销键、粘贴共用），不另写判定。
6. **纯判定下沉**：`shouldTriggerSelectAll` 进既有 `src/lib/canvas-keys.ts`（该文件已是这类判定的落点），
   微调坐标的计算是纯函数。
7. 不新增 UI，无视觉变更。

## 成功标准

1. 画布上按 ⌘A（Windows：Ctrl+A）→ 只选中**当前视口内**的卡；屏外的、被类型筛选隐藏的都不选。
   平移 / 缩放后再按，选中集随之改变。
2. 焦点在搜索框 / composer / 文本编辑器里按 ⌘A → 全选文本，画布选区不变。
3. 选中一张卡按 `→` → 卡右移一个网格，**刷新后位置仍在新处**（现状会退回）。
4. 连按 5 下方向键后 ⌘Z → **一次**退回到 5 下之前的位置。
5. 相隔 500ms 以上的两段微调 → 两步撤销。
6. `Shift+方向` 步长更大（RF 内置 ×4），同样落库。
7. 多选后方向键 → 整组同步位移，全部落库，一次撤销全退。
8. 空格临时平移与 ⌘ 点击多选行为不回退（本轮不碰它们，只在验收里复测）。
9. 微调期间不产生每帧的坐标 PATCH —— 停手后一次性写（否则连按 20 下就是 20 轮请求）。

## 方案

RF 不给「方向键移动完成」的回调，所以只能自己听 `keyup` 收口：

| 文件 | 职责 |
|---|---|
| `src/lib/canvas-keys.ts` | 加 `shouldTriggerSelectAll(e, activeEl)`（与既有两个判定同款结构） |
| `src/lib/nudge.ts`（新） | `isArrowKey(key)` + `NUDGE_COMMIT_MS`；纯常量与判定，便于单测 |
| `src/components/canvas/AssetCanvas.tsx` | ⌘A → `setSelection(visibleAssets.map(id))`；方向键 keydown 时记「第一下之前的坐标」，停手 500ms 后一次性 `setAssetPositions` + `persistAssetPositions` + `pushUndo` |

微调收口的时序（要点在于**不能在 keydown 时就写**）：

```
第一下 keydown → 若无进行中的微调,快照 store 里的当前坐标(撤销目标)
每一下       → RF 自己改内部状态(我们不拦,也不写库)
停手 500ms   → 从 RF 读最终坐标 → 一次 setAssetPositions → pushUndo(快照) → persistAssetPositions
```

`isDraggingRef` 那条既有防线要一并考虑：微调期间 store 与 RF 会短暂不一致（RF 领先），
若此时 sync effect 跑一遍就会把位移冲掉 —— 与拖拽期同一原因，故微调期间同样置该标记。

## 明确不做

- **⌘⇧Z 重做**：与撤销一期的决定一致（不做 redo）。
- **Tab 遍历卡片**：RF 的 a11y 已提供节点焦点，本轮不叠自己的一套。
- **方向键切换选中**：见约束 1。
- **自定义步长设置项**：网格 10 + Shift ×4 够用，不加偏好项。

## 真机验收（2026-08-04，dev :3010，项目 Star Whisper-v82，33 张卡）

手法：合成键盘/鼠标事件驱动真实 ReactFlow；状态经仓库自带的 dev 句柄 `window.__store` 读取；
坐标 PATCH 次数用包一层 `window.fetch` 统计。

已验：

1. **⌘A 只选视口内**（口径修正后复测）：zoom 0.43 时视口内 19 张、选中 19 张；放大到 0.98 后视口内 11 张、
   选中的正是同一批 11 张（逐个 label 比对一致）。叠加类型筛选：只开 Image 时视口内 4 张、选中 4 张且 `kind` 全为 `image`。
   初版实现成「跟随类型筛选、不看视口」，Nick 真机测出屏外卡也被选中 —— 已改。
2. **⌘A 在搜索框里放行**：⌘K 聚焦搜索框（`activeElement` 为 `input[placeholder="Search ..."]`）后按 ⌘A，
   画布选区保持 0 不变。
3. **方向键微调真正落库**（本组核心）：选中 `terrain_snow` 连按 5 下 `→` → DOM `850`、**store 也 850**
   （修前 store 会停在 800）；**重载后仍是 850**，即真的写进了后端。
4. **微调期间零请求**：连按 5 下期间坐标 PATCH 数为 **0**，停手收口后共 **1** 次。
5. **连续微调合并为一步撤销**：5 下只往撤销栈加 1 格；相隔 >500ms 的两段微调 → 2 格。
6. **多选整组微调**：3 张 terrain 卡一起按 3 下 `↓` → 三张同为 `+30`，撤销栈只加 1 格，
   ⌘Z 一次三张全回原位。
7. **空格平移不回退**：按住空格拖 pane，视口精确平移拖拽量，pane 挂上 `draggable`。

**未验到的**：

- **⌘ 点击多选**：合成 `MouseEvent` 带 `metaKey` 打不进 RF 的点击处理（上一轮 align-guides 验收也遇到同样限制），
  只拿到 1 个选中。该路径本轮未改动（RF 默认 `multiSelectionKeyCode = Meta`），故按「未验」记录，不当作通过。
- **`Shift+方向` 的 ×4 步长**：由 RF 内置提供、与本轮收口逻辑同一条路径，未单独测。

**一处噪声**：一段把空格平移与合成 ⌘ 点击混在一起的脚本触发了 RF 的
`Maximum update depth exceeded`（栈落在 `<ReactFlow>` 渲染路径内）。重载后单独复跑空格平移正常，
正常交互模式下未复现 —— 与 align-guides 那轮同款的合成事件产物。但它打断了当次 ⌘Z 的坐标回写，
导致两张 terrain 卡的 `+30` 留在了后端（已用 store 句柄精确改回，重载后 32 张卡坐标与验收前逐张一致）。

**另一处噪声**：口径修正后的第一次 `pnpm test` 有 1 个文件 6 条失败（恰好等于新增的 `selectAllIds` 组条数），
但我没把那轮输出留下来，无法指名。随后 **4 轮全量全绿**（242 文件 / 2599 用例），
`offscreen.test.ts` 单独连跑 3 次也全绿。那轮与 dev server 被 kill 同时发生，按负载类偶发记录 —— 未定位，不当作已排除。

**另注**：画布上有一张不属于本轮验收的卡（`generate a colorful bird`），验收期间其坐标相对我的首份快照
差了 `(-10, -20)`。我全程只按过 → / ← / ↓，从未按 ↑，位移方向对不上，判断不是本轮造成的，故**未动它**。
