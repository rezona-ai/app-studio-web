# 画布交互打磨第二波（2026-08-12）

承接同日的 `2026-08-12-canvas-ux-refinements.md`。上一波把五处交互从「功能已通」推到「手感可用」，这一波是它落地后回归出来的四条：三条视觉/信息呈现，一条是上一波「放开对齐限制」直接引入的回归 bug。

## 目的

1. Toast 的撤销入口从下划线文字变成一个真按钮 —— 现在它看起来像正文里的超链接，不像「可以点的补救动作」。
2. 生成弹窗的积分消耗从「`18 credits` 灰色小字」变成「闪电图标 + 数字」，且**弹窗一打开就有东西可看**（在等报价时给 spinner，报不出价时给占位符），而不是像现在这样凭空出现、凭空消失。
3. 资产列表面板从画布左侧垂直居中挪到左下角。
4. **修 bug**：上一波放开对齐限制后，卡片坐标可以带小数；成组时把这个浮点包围盒原样发给后端 int 字段，导致「圈成一组」失败。

## 约束与决策

### 1. Toast 撤销按钮化

- **复用 `Button`**（`src/components/ui/Button.tsx`），不新建按钮种类、不自写按钮样式（UI/UX 范式硬约束）。
- **填充随主题翻**（实机验收后修正）：初版按「Toast 底恒浅色 ⟹ 按钮也该恒浅色」推导，取 `.btn-raised`。实机看下来这个推导错了 —— 深色主题下浅灰按钮几乎融进浅黄底（终审 M9 量过：描边对比约 1.34:1，低于 WCAG 1.4.11 的 3:1），看不出是个可点的东西。改为浅色主题取 `raised`、深色主题取 `raised-active`（深渐变 + 白字），落在恒浅的卡片上对比更强，也与深色 UI 的控件语汇一致。为此给 `Button` 加 `variant`，与 `IconButton` 的同名 variant 共用 `globals.css` 那两个类。
- **不能直接用 `submitVariant(active, dark)`**：那个函数服务于 composer 的**深色底**，在 dark 下返回的是浅按钮，结论正好相反。
- 尺寸收紧到 `px-2.5 py-1` / `text-[13px]`，以匹配 Toast 的 `py-3` + 22px 行高，不把卡片撑高。
- **行为一字不改**：仍然传 `shown.action.token`（只撤这一条、不弹栈顶），仍然**不** `clearToast()`（`undo()` 内部要写「已撤销：X」，清掉等于把自己的反馈吞了）。这两条都是上一轮评审确立的，改样式不碰它们。
- Toast 带 `action` 时不因 hover 暂停自动消失的规则也不变（按钮在 ⟺ 真能撤销）。

### 2. 生成弹窗积分展示

**形态**（用户拍板）：位置不动 —— 仍在提交按钮左侧、同一行，图标与数字并排、行内居中。

**与提交按钮成一组**（实机验收后补充）：报价与提交包进 `ml-3 flex items-center gap-3`。两个原因都是实机才看出来的 —— ① 外层行是 `items-end`（让参数 pill 与提交按钮底边对齐），chip 跟着沉底会比按钮中心明显偏低；② 外层只有 `gap-2`（8px），而左侧表单组有 `flex-1` 吸满余量，那 8px 就是 chip 与最后一个参数 pill 之间的实际间距，视觉上贴死。分组后「价格 + 提交」成为独立的一块。

- 图标用**已有的** `figAsset.credit`（`public/figma/icons/credit.svg`），恒 `--color-teal`，与预览区账户条的 credit 闪电同一套语汇。不新增图标资源。
- 数字去掉「credits / 积分」单位文字（图标已经承担了「这是积分」的语义）。区间价仍是 `min–max` 两个数。
- 金额继续走 `formatCreditExact`（带千分位）—— 仓库其余积分展示处一律格式化，不格式化会出现「生成表单 54000 / 充值弹窗 54,000」的不一致。

**三态**（用户拍板：打开即发 + spinner；报不出价显示占位符）：

| 态 | 显示 | 说明 |
|---|---|---|
| 加载中 | 行内 spinner | 打开弹窗**立即**发请求，不等 300ms |
| 有价 | `⚡ 18` / `⚡ 10–54` | 就地替换 spinner |
| 报不出价 | `⚡ —` | 无定价 / `billable=false` / 请求失败，一律同一个占位 |

- **首次请求跳过 debounce，后续改参数仍走 300ms**：debounce 存在的理由是挡住连续调参，而「刚打开弹窗」不存在连续调参。同时**改参数期间不退回 spinner**，保留旧价直到新价到达 —— 否则每调一次参数价格就闪一下空白（这是 `useGenEstimate` 现有注释里明确要避免的）。
- 占位符 `—` 配 `title` + `aria-label` 说明「无法估算」，走新增 i18n 词条（11 语）。**已知代价**（用户已认可）：占位符有被读成「免费」的风险；`title` 是唯一的缓解手段，不足以完全消除。
- 占位符替代了现有的「报不出价整块不渲染」。这不违反「绝不编数」——`—` 不是一个数，它明说的是「没有数」。
- 加载中的 spinner 复用全站行内 spinner 惯例（`animate-spin rounded-full border-2 border-[var(--color-line-2)] border-t-[var(--color-muted)]`，见 `toolPill.tsx` / `ProjectMenu.tsx` / `AttachmentBar.tsx`），**不引入新 keyframes**。`animate-spin` 是全站刻意不在 `prefers-reduced-motion` 里禁用的唯一动画（旋转是「没卡死」的唯一指示），沿用。
- 三态占位宽度不必强行恒定：三种内容宽度接近，且提交按钮 `shrink-0` 靠右固定，行高不变即够 —— 弹窗高度不跳是硬要求，横向几像素的位移不是。
- `useGenEstimate` 的返回契约从 `Estimate | null` 变成三态（loading / ready / none）。它现有的两条不变式必须保住：① 报价按 `kind` 归属，切类型立刻失效；② 依赖用请求体摘要 `signature` 而非对象身份，否则每帧一发请求。

### 3. 资产列表面板挪到左下角

- 定位从 `left-5 top-1/2 -translate-y-1/2` 改为 `left-5 bottom-5`，与底部缩放工具条、右下类型筛选按钮**同一条底线**（用户拍板）。
- 面板向上生长，高度仍按内容自适应并夹在 240～520px（上一波刚定的规则不动），但可用高度的算法基准从「垂直居中，上下各让 6rem」改成「自底向上，只让顶部搜索栏」—— 底部不再需要为工具条留空间，因为面板与工具条现在共用底线。
- **重叠与层级**（初版把阈值估成 ~700px，实测后重新拍板）：工具条实测宽 **464px**（`p-2` 16 + 11 项 368 + 10 个 gap 80）居中，面板右边缘 = `left-5` 20 + `LIST_W_DEFAULT` 300 = 320px，故重叠条件是**画布列宽 < 40 + 2×300 + 464 ≈ 1104px**。而 Chat 默认宽是 **518px**（`sidebar-fit.ts:8`）—— 1512 屏的画布列只有 ~984px，**默认配置下就重叠约 60px**，恰好落在工具条最左的「新增资产」按钮上（工具条上唯一的造东西入口）。这不是边缘情况。
- 处置：**保持贴底基线，让工具条压在面板上层**（用户拍板）。实现靠 **DOM 顺序**而非 z-index —— z 阶梯明令不插新值、画布 UI 一律 `z-10`，同层时后渲染者在上，故把 `<AssetListDrawer />` 移到 `<ZoomBar>` **之前**。工具条所有按钮恒可点。
- **剩余已知代价**（用户已认可）：重叠时面板右下角那几行的**右半段**被工具条盖住（行是全宽 `<li>`，点左半段仍能选中，所以不是「整行点不到」）。可关掉列表、拖窄面板或拉宽窗口避开。不加自适应躲避逻辑。
- **DOM 顺序管不到 ReactFlow 内部**（评审 I4，核实成立）：minimap 是 `.react-flow__panel`（`z-index:5`），`NewAssetsBadge` / `GenTaskBadge` 同样渲染在 `<ReactFlow>` 内，而 ReactFlow 根 div 自带 `position:relative; z-index:0` 自成层叠上下文 —— 面板作为它的后继兄弟**恒在这批之上**，改 DOM 顺序无效（改 z-index 则违反 z 阶梯约束）。几何上 minimap 占自底 84–244px、面板 `min-h` 240 恒占 20–260↑，竖向恒重叠；横向在 `canvasW < 880`（面板 300 宽）时相接，面板拖到 0.45 上限则阈值升到 ~1166，**默认屏幕即被盖住**。minimap 是可 pan/zoom 的交互面板，被盖住时那部分点不到。本轮不处理（要改就得动 minimap 自身的落位，属独立一轮）。
- 触发按钮（`AssetLibraryButton`，左上 `left-4 top-4`）位置不变 —— 它与搜索栏、工具条的关系已经稳定，这一条只动面板。

### 4. 成组失败（坐标浮点）

**根因已定位**：`createGroupFromSelection`（`src/store/actions.ts:1283`）把 `boundingBoxOf` 的输出原样 `POST` 给 `/canvas/groups`：

```
const geom = boundingBoxOf(picked, GROUP_PADDING);
created = await pgcApi.createCanvasGroup(pid, { name, ...geom, color });
```

而 `boundingBoxOf` 只是对卡片 `position` 做 min/max 加减 padding，不取整。同文件其余每一处几何写入口**在出网时**都取了整（1407/1458 的 `updateGroupGeometry`、1569/1616/1672/2579 的卡片落位），注释写明「后端 `canvas_x/y` 是 int，取整再传」——**建框是唯一连出网都没取整的那处**。上一波放开对齐限制前，卡片坐标恒为 `SNAP_GRID`(10) 的倍数，浮点根本不会出现，这个漏洞被吸附掩盖着；放开后立刻暴露。

**修在 `boundingBoxOf` 内**（纯函数层），而不是在请求处补一个 `Math.round`：

- 本地 `groups` 里的几何与发给后端的**同一个值**。在请求处取整会让本地留浮点、服务端存整数，刷新后框跳半个像素 —— 这类「前后端同一几何两份值」的分歧正是上一波终审 M5/M-d 反复处理的病灶，不该再造一个。
- 取整口径：`canvas_x/canvas_y` 用 `Math.floor`、`width/height` 用 `Math.ceil`（且宽高对**取整后的原点**重算，否则右下边界会缩回浮点框内侧）。**不能一律 `Math.round`** —— round 可能把左上角往右下挪、把宽高往小收，两头同时收缩会让本来贴边的卡片被挤到框外（`groupHitFor` 按中心点判定，边缘卡会掉组）。floor/ceil 保证整数框**恒包含**浮点框（各边最多外扩 1px）。
- ~~`boundingBoxOf` 整数化让 `groupHitFor` 的边界判定更稳定~~ —— **这条理由不成立，评审已推翻**：`boundingBoxOf` 全仓只有一个生产调用方，并不直接喂 `groupHitFor`；且 `centerOf` 仍是浮点（`position + w/2`），把框整数化只是把浮点挪到比较的另一侧，并未消除边界噪声。上面两条（后端 int、本地与出网同值）加「外扩保证不掉组」才是真正的理由。留此记录，免得后人按错理由推导出「卡片坐标也该整数化」。
- 铁律 1：先写复现该 bug 的失败测试（`src/lib/canvas-group.test.ts` 断言浮点输入 → 整数输出且外扩；`src/store/actions.test.ts` 断言 `createCanvasGroup` 收到的请求体四个几何字段均为整数），再改实现。

## 成功标准

1. Toast 的 Undo 是一个浅灰渐变实心按钮（`.btn-raised`），深色主题下按钮仍浅色、文字仍深色可读；点它只撤这一条，且随后的「已撤销：X」Toast 能正常出现。
2. 打开生成弹窗，提交按钮左侧立刻出现 spinner；报价回来后就地变成「⚡ + 数字」（闪电为 teal，数字带千分位，无单位文字）；调参数期间旧价保持不闪。
3. 后端报不出价（`billable=false` / 半个区间 / 请求 500）时显示「⚡ —」而非空白，悬停有「无法估算」提示。
4. 资产列表面板底边与缩放工具条、右下筛选按钮对齐成一条线，向上生长，仍不遮挡顶部搜索栏；卡少时不拉满高度；**列表打开时工具条每个按钮仍可点**（含被面板横向覆盖的那段）。
5. 卡片位于非整数坐标（关闭对齐后自由拖拽所得）时，「圈成一组」成功：请求体四个几何字段均为整数，画布上框的位置与刷新后一致，且原本贴框边缘的成员卡不掉组。
6. `pnpm lint` / `tsc --noEmit` / `pnpm test` / `pnpm build` 全绿。

## 评审处置

### 任务 1（成组取整）独立评审：Critical 0 / Important 0 / Minor 6

变异检验（评审复算 + 随机 200k 组）确认测试有判别力：`Math.round`、`Math.trunc`、「先 ceil 原宽高再配 floor 原点」、「宽高用 floor」四种变异全部被「整数框恒包含浮点框」那条断言杀掉。负坐标这个输入是杀掉 `trunc` 的关键。

采纳并已改：注释里指代已删变量 `memberIds` 的措辞（改为「成员快照」）、测试的 `Object.entries` 改显式四键（防 `GroupGeometry` 将来加非数值字段时误报）、给「本地框 == 请求体」那段自反断言补注它真正防的回归（重映射只换 id、不采用服务端回包几何）、以及上面 §4 里被推翻的那条理由。

与 plan 1.1 的偏离（记录，无实质缺口）：plan 要求补一条「整数输入输出逐字节不变」的断言，实际改为在注释里指向既有三条整数用例——它们已把四个字段全部钉死，等价成立，不另加冗余测试。

### 任务 2+3（Toast 按钮化 + 列表贴左下角）独立评审：Critical 0 / Important 4 / Minor 9

**I1 尺寸收紧全部失效（已修，本轮最实的一条）**：`Button` 把调用方 `className` 拼在末尾，但 Tailwind 无 `!important`、仓库也没接 tailwind-merge —— 同特异性下胜出方由**生成样式表的规则顺序**决定，与 class 属性顺序无关，而 v4 按刻度升序排。`pnpm build` 后逐条量过字节偏移：`.px-2.5`(41357) < `.px-3`(41408)、`.py-1`(41965) < `.py-2`(42060)、`.text-[13px]`(44329) < `.text-[14px]`(44359) —— 三条收紧全是噪声，撤销按钮实际渲染成 `px-3 py-2 text-[14px]`，卡片被撑高约 10px（37px vs 意图 27.5px），正是 §1 明令不许的。修法：把尺寸变成 `Button` 的**组件契约**（`SIZE` 表内部互斥选取，新增 `size?: 'md' | 'sm'`），Toast 传 `size="sm"`。这样 jsdom 里能断言「收紧类在、默认类不在」，尺寸决策从零覆盖变成可钉住（已做变异检验：去掉 `size="sm"` 即红）。

**I2 / I3（已修）**：`AssetListDrawer` 文件头注释写成「重叠时由面板压在上层」，与实现（工具条在上）正好相反 —— 这是我改 DOM 顺序后没回头改注释；同文件的已知代价注释还留着被推翻的 `~700px` 旧阈值。两处都会让下一个读者照反的结论去改 DOM 顺序，把「新增资产点不到」复活。

**I4（不修，记录见 §3）**：DOM 顺序管不到 ReactFlow 内部的 minimap 与 badge。

采纳的 Minor：补 `z-10` 断言（顺序只在同层叠层级下决定上下，加个 `z-20` 就绕过原断言）、`listOpen` 用例收尾复位（它属 UIState，不在 `beforeEach` 重置范围）、修正搜索栏高度注释（`h-10` 是 40 不是 44，原估高 4px 属保守方向、结论不变）、`list-drawer.ts` 的 `0.45` 上限改写为当下真实理由（原理由「与右侧属性面板分横向空间」已随上一波删面板而失效）、把「那几行点不到」改准为「那几行的右半段点不到」（行是全宽 `<li>`，左半段仍可点）。

观察项（不改）：Toast 卡 8px 圆角里嵌 10px 圆角按钮略不齐（两者都在允许档位内）；`.btn-raised` 的 `0 0 0 1px #d4d4d4` 描边在 Toast 浅底上约 1.34:1，低于 WCAG 1.4.11 的 3:1，但按钮有渐变填充 + 投影，实际可辨 —— 不为它引入新令牌。

**同坑另一处（下一轮候选）**：`src/components/chat/ReconnectBanner.tsx:43,50` 的 `px-2 py-1 text-[13px]` 因同一原因全部失效，那颗按钮实际是 md 尺寸。现在 `Button` 有了 `size` prop，迁过去是一行改动，但它属重连横幅的视觉、不在本轮验证清单里，故不搭车改。

### 终审（全分支）：Critical 0 / Important 2 / Minor 10

终审复算并确认了 §评审处置 I1 的字节偏移证据，也把 `useGenEstimate` 的 13 条状态转移逐条走过——除下面记录的两条既有缺口外，无竞态、无永久 spinner。

**I1（已修）**：`GenerateForm.tsx` 调用点上方的注释仍写「报不出价返回 null 则整段不渲染」，是本轮亲手推翻的两条语义。这是「注释与实现相反」在本回合第三次复发（前两次是列表面板的层级与阈值），同一类问题反复出现说明改实现时回头扫注释这一步做得不够。

**I2 可访问文本丢失（已修）**：单位从词条（`'{{credits}} credits'`）改成图标后，`FigIcon` 的 primary 档是 CSS mask 的 `<span aria-hidden>` —— 没有 `alt`、没有文本节点，于是 AT 只能读到紧挨「Generate」的裸数字「8」。这是本轮删词条造成的信息损失，spec §2 只讨论了视觉形态、没讨论 AT，属设计树上的默默假设。修法：chip 加 `role="img"` + `aria-label`（`role` 是必须的——`aria-label` 在无 role 的 `<span>`(generic) 上属 ARIA 1.2 的 prohibited attribute，AT 可合法忽略，那样占位符的「唯一缓解手段」在 AT 侧等于不存在）；单位复用既有 `preview.credit`，零新增翻译。

**M8 切项目首价被拖延（已修）**：`switchProjectSession` 不清 `genForm`，故弹窗开着切项目是可达路径，而 `sentRef` 不重置会让新项目的首价白等 300ms——「打开即发」在这条路径上不成立。改为 pid 变化即视同重新打开。

**M4 文案（已改）**：`Unavailable / Nicht verfügbar / …` 这类无主语措辞易被读成「功能不可用」而非「价格算不出」。既然 title 是占位符风险的唯一缓解手段，它不该在默认 locale 上最弱 —— 七语改为「Estimate unavailable」式明确措辞（ja/ko/zh/zh-TW 原本已明确，不动）。

其余采纳：spinner 显式 `inline-block`（原先靠 flex blockify，换宿主会塌）、给 loading 态补「紧邻提交按钮左侧」断言（该不变式此前只覆盖 ready 态）、修正测试注释的搜索栏算术（56+20 而非 60+16）、`list-drawer.ts` 的 0.45 结论改准（任何画布宽都盖不满，不是「常见宽度下达不到」）、`useGenEstimate` 的 `GenerateFormHost` 卸载理由改准（它没有 `key`，真卸载靠入口必经 `genForm=null`）。

### 记录（不修）

- **`billable === false` 的语义方向相反**：它是计费灰度关闸，含义是「不会扣费」，而现在会显示成「⚡ —（Estimate unavailable）」——比改动前的「整块不渲染」更吵，且方向与事实相反。关闸是全局的，一旦打开每个生成弹窗都会看到。要修得给 hook 加第四态（free），超出本轮 §2 的三态设计，故记录。**这条值得下一轮优先看**。
- **无请求超时 → spinner 可能长转**：`estimateGenerate` 没有超时，代理 stall 时 loading 是纯派生的「还没回来」。改动前同样情形只是一直不渲染，噪音更小；加超时超出本轮范围。
- **拖宽把手底部约 56px 抓不到**：重叠区里把手最下面那段落在工具条之下。把手总高 ≥224px，其余可用，不影响可用性。

### 遗留：分组框缩放/移动路径的「一份几何两份值」（本轮**不修**）

评审发现并经核实：`updateGroupGeometry`（actions.ts:1406）与 `moveGroup`（1456）**只在出网时** `Math.round`，写进 store 的仍是 `patchGroupLocal(gid, {...geom, w, h})` / `translateGroup` 的原始浮点。卡片那条路径靠 `reference.position` 保留原始浮点所以两边自洽，而**框没有 `reference`**（`canvasGroupToGroup` 只读四个几何字段），于是刷新后本地浮点被服务端整数取代。后果两条：① 框相对成员最多位移 0.5px（视觉可忽略）；② 中心点距框边不足 0.5px 的成员，刷新后会变成「仍在组内但中心已在框外」，要到下一次缩放才自愈。

本轮**有意不动**，理由是它超出 spec §4 的范围（§4 只讲建框），且改动有实质风险：`updateGroupGeometry` 的失败补偿带 ABA 仲裁（`cur.x !== geom.x` 逐字段比较），本地改写取整值而仲裁仍比原始 `geom.x` 会让它误判「被后一次缩放超越」；`moveGroup` 单方面取整框而不取整成员坐标，会在拖框时引入亚像素错位。要修就得把三处几何写入口按同一套外扩口径统一（取整一次、同时写本地与请求体），那是独立的一轮。

**结论**：这是既有的亚像素级问题，不是本次改动引入的回归。下一轮候选 —— 但优先级比「亚像素」听起来要高一点：本轮只在**建框**这一处立起了「本地与出网同值」，紧接着的第一次拖框或缩放就会重新破掉它（终审补充）。

- 不改动估价的请求体构造（`estimateBody`）与三形态归一（`normalizeEstimate`）的既有语义，只在其外包一层三态。
- 不改 `AssetLibraryButton`、搜索栏、缩放工具条、筛选按钮的位置。
- 不为「窄画布下列表面板与工具条重叠」加自适应躲避逻辑（用户已认可该代价）。
- 不改 Toast 的自动消失时长、hover 暂停规则、撤销 token 语义。
