# 两侧边栏折叠把手（放大 + 对话栏可收起）

2026-08-17 · 分支 `feat/sidebar-collapse-handles`

## 需求与决策

用户诉求两条：预览那枚「扩到最大宽度」把手太小不好发现也不好点，调大；左侧对话栏加同款按钮收起/展开。

盘问定下的三条口径（bounded 路径，未单独出设计稿，本文即结论沉淀）：

1. **尺寸**：宽度定 24（用户指定），高度按原 16×88 等比 ×1.5 → **24×132**，图标 12→14。
2. **收起语义**：Chat 列宽收到 **0，完全隐藏**（不是窄轨、也不是收到 `CHAT_WIDTH_MIN`），画布吃满左侧空间。
   > ⚠️ 2026-08-18 修订：原做法是「Chat 列与分隔条一并不渲染」，代价是 ChatPanel 真卸载、滚动位置丢失。为给收放加过渡已改为**始终渲染 + 宽度过渡到 0**（内层恒以 `chatW` 布局），那条代价随之消失。以现状为准。
3. **可见性**：沿用「默认 `opacity-0`，hover 才浮现」。**例外**：Chat 收起态、以及 compare/files 覆盖态必须常显（理由见下「坑清单」3、4）。

## 坑清单（评审逐条打出来的，勿重蹈）

1. **全宽态不得用「宽度 ≥ 上限」反推**。上限随收放对话栏 / 缩放窗口变化，反推会让全宽态凭空翻假；再点一次展开就把全宽宽度冒充成用户的常态宽，「恢复」从此原地不动。同一个坑踩了两次（第二次是「常态宽回退到期望宽」，自动全宽后刷新即触发，恢复只能退 1px 空转）。现为显式持久化状态 `workspace.previewFull`，期望宽恒是用户拖出来的常态宽，渲染宽由状态派生。
2. **把手热区不得骑缝**。骑在边栏边缘上会吃掉 ChatPanel 消息区的滚动轨、预览账户条的内边距。现在定位容器 `pointer-events-none` 只摆位，可命中的只有 `clipPath` 裁出的本体，且整块落在边缘的**画布侧**。
3. **不要用「画布余量不足就藏 Chat 把手」这类闸门**。曾为避免两枚把手撞车而加，结果 compare/files 与窄视口下「收起对话栏」的唯一入口静默消失 —— 静默失能比 24px 误触更糟；把手改落画布侧后两枚实测只重叠 1px（分隔条那一列），闸门收益远小于代价，且判据算式留在组件里正是「同一判据两处各写一份」的来源。
4. **覆盖态（compare/files）的隐形把手是误触不是死区**：那条 24px 命中带正压在文件树左缘，depth 0 的折叠箭头就在里面，点它会莫名收起对话栏。故这两态 `pinned` 常显，让误触退化成「点到一个看得见的按钮」。
5. **纯点击分隔条不算拖拽**（`startResizeWith` 的 `moved` + 横向死区）。分隔条热区仅 3px 且紧贴把手边缘，瞄偏很容易点到；无条件 commit 会让预览侧把全宽冒充成期望宽、Chat 侧把碰撞消解值写成期望宽 —— 后者直接破坏 `fitSidebars`「期望宽只读不改」的不变式（视口放大后再回不到用户选的宽度）。按下时竖向微抖很常见，故只认横向位移。
6. **退出全宽要放在首次移动**，与该帧的新宽度同批写入；放在 `pointerdown` 会先跳一帧常态宽再跳回来（渲染读的是 `previewW`，它直到首次 `pointermove` 才被写）。
7. **`eslint-disable` 抑制不了东西时必须删**：setState 包进嵌套函数后 `react-hooks/set-state-in-effect` 不再穿透报点，留着那行会被报成 `Unused directive`，把仓库 lint 基线从 11 抬到 12。

## 评审处置

三轮干净上下文评审（每轮只给需求 + commit 范围 diff）：

- 第一轮：1 Critical（把手盖死「恢复预览宽度」）+ 3 Important（热区吃边栏内容、常态宽污染、`collapsedRef` 零覆盖）→ 全部采纳修复。
- 第二轮：1 Critical（常态宽回退引入的新回归）+ 3 Important（余量闸门砍掉收起能力、判据两处各写、常显例外零覆盖）→ 全部采纳；`previewFull` 改显式状态、闸门整块退役。
- 第三轮：0 Critical + 2 Important（纯点击落库 + 起拖闪帧、覆盖态隐形误触）+ 3 Minor → 全部采纳。

**记录不修的项**（评审判定可接受）：`maxPreviewWidth` 恒扣 2px 分隔条，收起态少算 1px（方向保守安全）；收起态常显例外不受余量约束（视口 <378px 才可达，桌面固定布局不可达）；Chat 卸载丢消息区滚动位置；把手沿用既有外观未加 popover 阴影/模糊；图标取 14 而非等比的 18；测试靠 `button.parentElement` 取定位容器（依赖同文件把 `Tooltip` mock 成透传，已在断言旁注明）。

## 回归锁
