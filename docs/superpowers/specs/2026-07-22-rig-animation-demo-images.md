# Create animated character 动作演示图设计

## 背景与目标

当前动作选择器沿用 Figma 导出的 11 张像素风角色图。它们存在三类问题：

- 图像动作与后端实际 preset 不完全对应，例如 `grab/block/special/down/pose` 无法覆盖 `climb/dive/shoot/fall/turn`。
- 非人形 preset 没有图示，白底空块无法帮助用户理解动作。
- 单一角色定格缺少运动方向、起止姿态与节奏，缩到 48×48 后动作辨识度进一步下降。

本次目标是按照后端 `animation_presets` 的完整合法集合，为 11 个人形动作和 5 个非人形动作生成一套统一、可辨识的演示图，并由 preset 全名稳定映射；未来未知 preset 仍安全退化为空白缩略图。

## 成功标准

- 覆盖 `walk / idle / run / jump / climb / dive / slash / shoot / hurt / fall / turn`。
- 覆盖 `quadruped:walk / hexapod:walk / octopod:walk / serpentine:march / aquatic:march`。
- 每张图在 48×48 实际展示尺寸下仍能辨认主体拓扑、运动方向和动作类别。
- 同类主体、相机、背景、光照和视觉语言一致；图片不包含文字、水印或品牌标识。
- 输出使用 WebP，路径经 `assetPath()`，不改变后端 preset 契约。

## 方案比较

### 方案 A：单帧姿态截图

每个动作只展示一个关键姿态。资产最轻、实现最简单，但与现有方案的问题相同：`idle`、`walk`、`run`、`turn` 等动作在小尺寸下容易混淆。

### 方案 B：短循环动画 WebP

每个动作播放四帧循环。表达最直接，但动作卡同时出现时会形成持续闪动，用户难以聚焦；动画图片也无法可靠响应 `prefers-reduced-motion`，与项目动效约束冲突。

### 方案 C：关键帧叠影演示图（推荐）

在单张图内用“主姿态 + 半透明前后帧叠影 + 方向弧线/速度线”表现运动过程。它兼具静态资产的性能与可访问性，又能在小尺寸中表达动态。用户无需等待动画播放，所有动作可直接比较。

## 视觉设计

### 共通语言

- 画布：正方形、浅暖灰背景，边缘留足安全区；不生成文字和外框。
- 主体：低多边形 3D 训练人偶，哑光深石墨材质，关节使用 Taluna 青绿色识别点。
- 动态：主姿态不透明；前一/后一关键帧使用低透明青色叠影；方向弧线、速度线或冲击星芒使用珊瑚橙点缀。
- 相机：略高于腰部的 3/4 侧视角；主体始终完整入画，避免裁切。
- 光照：柔和工作室顶光，无复杂投影；保证缩小后的轮廓对比。

### 拓扑角色

- 人形：同一无脸中性训练人偶，11 个动作保持体型与材质一致。
- 四足：中性犬科机械训练体，突出四肢交替步态。
- 六足：昆虫式六足训练体，突出三足支撑交替。
- 八足：章鱼式八足训练体，突出触手波次推进。
- 蛇形：分节蛇形训练体，突出 S 形行波。
- 水生：流线型鱼类训练体，突出尾鳍摆动和向前推进。

## 动作构图

| preset | 演示重点 |
|---|---|
| `walk` | 左右脚交替、身体平移、短步幅 |
| `idle` | 重心轻微起伏、胸腔呼吸 |
| `run` | 大步幅、前倾、明显速度线 |
| `jump` | 蓄力、腾空顶点、落地方向 |
| `climb` | 手脚交替向上、竖直方向弧线 |
| `dive` | 向前下方跃出、身体伸展 |
| `slash` | 手持抽象训练短刃、横向挥砍弧线 |
| `shoot` | 双手持抽象训练器、后坐叠影、前向脉冲 |
| `hurt` | 受击后仰、冲击点与回弹方向 |
| `fall` | 失衡、下坠、向下速度线 |
| `turn` | 原地转身、脚步枢轴与旋转弧线 |
| `quadruped:walk` | 四足对角步态与前移 |
| `hexapod:walk` | 三足组交替支撑与前移 |
| `octopod:walk` | 触手波次抬起、接触、推进 |
| `serpentine:march` | 身体 S 形行波沿长度传播 |
| `aquatic:march` | 尾鳍左右摆动、身体向前游动 |

## 资产与映射

最终资产放在 `public/figma/rig/demos/`：

- 人形：`biped-<action>.webp`
- 非人形：`<rig-type>-<action>.webp`

`rigAnimationThumb()` 不再只取动作末段，而是先规范化完整 preset：

- `walk`、`preset:walk` 映射到 `biped-walk.webp`。
- `preset:quadruped:walk` 映射到 `quadruped-walk.webp`。
- 未知 preset 返回 `null`，维持现有安全退化。

## 非目标

- 不在前端复制“某种 rig_type 有哪些动作”的业务规则；动作列表仍完全来自 `precheck.animation_presets`。
- 不改变最多选择五个动作、默认动作或提交请求结构。
- 不新增自动播放动画、视频资源或新 CSS keyframes。
- 不修改生成后 GLB 动画播放策略。
