# 失败卡「修改后重试」改为**替换原卡**，而不是新增一张

> 触发：真机使用中，内容审核类失败卡点「修改后重试」→ 改完提交 → 画布上多出一张新卡，
> 原失败卡还在旁边。用户心智里这是"把这张卡重做一遍"，不是"再来一张"。

## 目的

让失败卡的「修改后重试」与「重试」（直接原样重发）在**卡的去留**上语义一致：
原卡消失、新卡落回它的位置；表单只是中间多了一步"改参数"。

## 现状（HEAD 实读）

| 事实 | 位置 |
|---|---|
| `openRetryForm` 刻意**不丢弃**原卡，新卡以原卡左上角为起点 + 避让（落旁边） | `store/index.ts:801,816-819` |
| 直接重发（`resend`）**丢弃**原失败卡并用 `pinAt` 占回原位 | `store/index.ts:794-795` |
| 占位卡落位已有 `pinAt` 语义：首张落指定点不避让，其余按真实尺寸避让 | `store/actions.ts:580-582` |
| `discardFailedCard` 已处理"孤儿卡不丢 / 有服务端 item 则发 DELETE"，并回报**实际有没有丢** | `store/index.ts:794` 的用法 |
| 成功卡也会走 `editForm`（agent 卡恒走），此时**必须不删** | `2026-08-07` 成功标准 6 |

即：所需的落位与删除机制都已存在，本轮只是把「表单这条路」接到同一套上，并加一个"何时接"的门。

## 盘问结论（2026-08-14）

1. **提交时才丢弃原卡**。打开表单不动原卡——用户可能改到一半关掉，那时卡（连同失败原因）得还在；
   点「生成」的那一刻才丢弃并占位。与直接重发的 `discarded` 语义完全一致。
2. **拖动过弹窗则尊重拖动位置**。`dropped` 的优先级不变（用户显式意图 > 替换语义）；
   没拖过才占原卡的位置。
3. **agent 失败卡一视同仁**，也替换。判据只看「是不是失败卡」，不看来源——否则同一个按钮
   对两类卡行为不一致。注意这对 agent 卡是**新行为**：它恒走 `editForm`，此前从不会被丢弃。

## 约束

1. **只对失败态替换**：`status === 'error'` 才丢弃原卡。成功卡的「以相同参数再生成」行为
   一字不变（原卡还在、不发 DELETE、新卡落旁边）——`2026-08-07` 成功标准 6 是回归项。
2. **复用既有机制，不新造**：丢弃走 `discardFailedCard`（孤儿不丢、DELETE、延迟删除都在里面），
   落位走 `pinAt`。不新增落位规则、不新增删除路径。
3. **丢弃失败就不占位**：`discardFailedCard` 回报 `false`（孤儿卡、卡已被用户删掉、跨项目残留）时
   退回现有的 `nearAt`（起点 + 避让）。判据是「原卡还在不在」，不是「原卡是不是失败态」——
   与 `resend` 那条同一句话。
4. **分层不破**：丢弃与落位判定属 store，`GenerateForm` 不得自己调 `discardFailedCard` 或算位置；
   UI 只在提交时向 store 要一次"这次该怎么落"。
5. **不持久化**：`genForm` 是瞬态 UI 态，本轮新增字段同样不落盘。

## 成功标准

1. 失败卡点「修改后重试」→ 表单打开，**原卡仍在画布**（此时关掉表单，一切照旧）。
2. 在表单里改参数后提交 → 原失败卡从画布消失（有服务端 item 的发 DELETE），
   新占位卡**落在原卡的位置**（首张不避让）。
3. `n > 1` 时首张占原位，其余按既有规则避让。
4. 拖动过生成弹窗再提交 → 新卡落在弹窗当前位置，原卡照样被丢弃。
5. 孤儿卡（`GEN_STATE_LOST`）不受影响：仍走「重新检查」，不进本路径、永不被丢弃。
6. 成功卡（含 agent 成功卡）走 `editForm` 时**不丢弃**原卡、新卡落旁边（回归）。
7. agent **失败**卡与前端失败卡行为一致：提交即替换。
8. 表单打开期间原卡被用户手动删除 → 提交不报错，新卡按 `nearAt` 落位。
9. `pnpm lint` / `pnpm exec tsc --noEmit` / `pnpm test` / `pnpm build` 全绿。

## 对既有 spec 的推翻

`2026-08-07-retry-path-guards` 成功标准 7「表单重试（`openRetryForm`）对失败卡 → 新卡落在旧失败卡
**旁边**，不再零偏移压住它」——本轮改为**占原位**。当时那条要解决的是"两张卡零偏移完全重合"
（`spawnAt` 跳过避让导致），而不是"必须落旁边"；原卡既然在提交时已经消失，重合问题自然不存在。
