# 分组框：标题条讲清量纲、成员数即时更新、Backspace 删框

日期：2026-08-13
状态：已批准（两条决策由 Nick 逐条确认）
前置：`2026-08-05-canvas-groups`（分组本体）、`2026-08-12-canvas-group-theming-and-menu`（框色与右键菜单）

## 目的

实机反馈三条，两条外观 / 交互、一条是 bug：

1. 标题条是「框名 + 成员数」两个 span 紧邻（`主角 3`），读起来像这个框就叫「Group 3」—— 量纲没说清。
2. 卡片移入 / 移出后成员数**不刷新**，要再点一下画布才更新。
3. 框没有键盘删除入口 —— 上一回合把 14px trash 按钮搬进右键菜单时，顺带丢掉了唯一的 tab 可达路径（已记在上一份 spec 的已知缺口 4，本回合正面解决）。

## 约束

- 不动几何 / 归属判定 / 删框语义：`canvas-group.ts` 的包围盒与命中判据、`deleteGroup` 的「拆框留卡 + 5 秒撤销」原样。
- 框**不进 RF 选区**（`selectable: false` 保持）：⌘A、橡皮筋框选、方向键微调、批量动作的口径一个都不许变。
- 键盘判据继续沉在 `lib/canvas-keys.ts` 的纯函数里单测，不在组件里写散装 if。
- i18n 沿用仓库既有做法：**不引入复数机制**（`_one/_other`），英文等语言用 `card(s)` 这类兼容写法 —— 现成先例是 `errors.positionSaveFailed` 的 `{{count}} card(s)`。俄语等多复数形式语言若上真复数，得为每个语言补 3–4 个形式，代价与收益不成比例。

## 决策

### 决策 1：标题格式 = 「框名 · N 张卡」

中点分隔 + 量词，量纲一目了然；`0 张卡` 也照常显示（空框只可能由「成员被拖空」产生，显示 0 比隐藏更诚实）。

- 框名与计数**分成两个语义单元**：框名 `truncate` 可截断，计数恒完整可见（计数被截掉等于没说）。
- 计数走 i18n 插值 `canvas.group.memberCount`（`{{count}} 张卡` / `{{count}} card(s)`），不在组件里拼字符串。
- 双击进改名态时**只替换框名那一段**，计数继续显示 —— 改名时也该看得见自己在改哪个框。

### 决策 2：Backspace / Delete 删框，目标 = 框自己的选中态

新增 store 字段 `selectedGroupId: string | null`，**不复用 `selectedIds`**（框进 RF 选区会让 ⌘A / 框选把框一起选上，Delete 到底删卡还是删框立刻歧义 —— 那正是当初刷 `selectable: false` 要规避的）。

- **进入**：框体空白处**无位移的左键点击** = 选中该框（框体本就是拖拽把手，拖是拖、点是选，互不冲突）。
- **视觉**：沿用全站「选中 = 描边转强调色 + 柔光外晕」语汇。框描边本就是品牌青，故选中态加一圈 `--color-teal-soft` 外晕（与 `.composer-card` 聚焦环同款），**不加粗边框** —— 加粗已被 drop 高亮占用，三态必须互相可辨。
- **退出**：点画布空白、选中任意卡片、切项目、框被删除。与卡片选区**互斥**：选框即清卡选区，选卡即清框选中（同一次 `set` 内完成，避免「两个选区同时非空」这种键盘层无法裁决的中间态）。
- **删除**：`Backspace` / `Delete` 走既有 `deleteGroup`（拆框留卡 + 5 秒撤销 Toast），**不弹确认** —— 与「单选卡片 Delete 直接删」一致，且删框无损（卡一张不少）。
- **判据**：新增纯函数 `shouldTriggerGroupDelete(key, hasSelectedGroup, activeEl, lightboxOpen)`，与卡片那条 `shouldTriggerCanvasDelete` 并列而非塞进同一个函数 —— 两者的「目标从哪来」不同，合并会让参数表变成一堆布尔。因两个选区互斥，同一次按键只可能命中其中一条。

### 决策 3（bug）：成员数即时更新

根因已定位：`persistDraggedNodes` 把归属即时写进 store（注释写着「成员数要马上对」），但 `isDraggingRef` 的复位排在 `setTimeout(0)`，而 store 更新触发的 sync effect 在这之前就跑完并撞上 `if (isDraggingRef.current) return` 早退；deps 此后不再变化，于是数量停在旧值，直到下一次点击改了 `selectedIds` 才补上。

修法：复位标记之后**补跑一次 sync**（复位与「放行」在同一个 tick 里成对出现），而不是把 `setTimeout(0)` 拿掉 —— 那个延迟是为了让 `onNodesChange` 的最后一帧位置变更先落定，去掉会让卡在松手瞬间弹回几像素（`2026-08-11-drag-commit-guards` 已经踩过）。

## 成功标准

1. 标题条读作「框名 · N 张卡」；框名过长时只截框名、计数仍完整；改名态下计数仍在。
2. 拖卡入框 / 出框后**松手即见**新数量，不需要多点一下画布。拖框整体移动时成员数**不变** —— 成员跟着框走，且拖框刻意不吞并路过的散卡（`2026-08-05-canvas-groups` 的「有意例外」，`moveGroup` 不做入组判定）。原先这条写成「拖框覆盖卡后也即见新数量」，与那条例外冲突，按实现与既有决策改正（评审 M6）。
   同一条不变式的另一半：拖框松手后框节点的 `data.group` 也必须跟上新坐标，否则紧接着抓缩放把手会读到陈旧 `x` 并把它落库（评审 I1）。
3. 点框体空白 → 框出现选中外晕；此时按 Backspace 或 Delete → 框消失、卡片留在原位、Toast 给 5 秒撤销。
4. 框选中期间 ⌘A 仍只全选卡片，方向键仍只微调卡片；选中卡片后框的选中态自动消失（反之亦然）。
5. 焦点在改名输入框 / 任何输入类元素时，Backspace 照常删字，不删框。
6. `pnpm lint` / `pnpm exec tsc --noEmit` / `pnpm test` / `pnpm build` 全绿。

## 明确不做

- 多选框、框与卡混合选区。
- 框的 tab 可达与 `Shift+F10`（框节点仍不可聚焦；本回合给的是「点选 + 按键」这条路径，纯键盘用户仍需鼠标点一下选中）。
- F2 改名快捷键（改名仍是双击标题条 / 右键菜单两个入口）。
- 手型工具 / 按住 ⌥ 时框体让开指针 ⟹ 那两种状态下点不中框、也就选不中（沿上一份 spec 已知缺口 2 的同一代价）。
