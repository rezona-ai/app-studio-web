# 刷新后恢复最新版本与完整轮次脚注 — 设计稿

日期：2026-07-24

## 背景与问题

Chrome 端到端测试稳定复现了两个刷新恢复问题：

1. 项目已有 Version 1～Version 3 时，刷新后预览回到服务端标记的 Version 1，而不是最高版本 Version 3。
2. 长回合完成后，页面内能看到 `模型 · Ran for ...`；刷新后最新 100 条事件不包含该回合的
   `run.started`，`seedHistory` 用这段局部事件整体替换已持久化的 `turns`，脚注随之消失。

两者共同暴露的是刷新恢复边界不清：

- 版本列表首载把后端 `is_current` 当成产品默认选择，但需求定义的默认值实际是“最新版本”。
- 历史事件接口返回的是有限窗口，而本地可重放检查点可能拥有窗口之外的轮次起点；有限窗口不能独立重建完整轮次。

## 目标与成功标准

- 每次页面冷启动或切入一个尚未加载版本列表的项目时，预览默认选中 `index` 最大的 ready 版本。
- 同一页面生命周期内，版本列表没有新增版本时，继续保留用户手动选择的旧版本。
- 新版本出现及 pending 版本完成时，继续自动前进到对应最新版本。
- 历史最新页缺少 `run.started` 时，只要持久化轮次的锚点消息仍在该页，刷新后继续展示该轮模型与耗时脚注。
- 不扩展后端契约，不增加额外请求，不持久化新的瞬态字段。

## 方案比较

### 版本恢复

#### 方案 A：继续信任后端 `is_current`

改动最小，但 `is_current` 表示后端当前标记，不等于产品要求的“刷新默认最新”，会保留现有问题。

#### 方案 B：持久化每个项目的 `activeVersionId`

能恢复刷新前的人工选择，但与“每次刷新默认最新”冲突，还会扩大持久化迁移与过期版本清理范围。

#### 方案 C：冷加载选最高 `index`，热刷新保持用户选择（推荐）

`loadVersions` 仍作为唯一入口：

- `versions` 为空且 `activeVersionId` 为空时，按最高 `index` 选择最新版本；
- 已加载状态下没有新版本时，保持 `activeVersionId`；
- 出现新版本或 pending 版本完成时，沿用现有自动前进逻辑。

最新版本按契约字段 `index` 比较，不依赖接口数组排序。

### 轮次脚注恢复

#### 方案 A：增大最新事件页大小

只能推迟截断，长回合仍可能超过窗口；并增加响应体与重建开销，不能从机制上解决问题。

#### 方案 B：刷新时持续向前翻页直到找到 `run.started`

可以完全依赖服务端事件，但每次刷新可能产生多次串行请求；还会把“首屏恢复”扩大成“全量历史加载”。

#### 方案 C：用持久化轮次补齐最新事件窗口（推荐）

`seedHistory` 把当前 `state.turns` 作为重建基线：

- 重放窗口内事件时按 `runId` 更新已有轮次，避免重复建轮；
- 终态按 `runId` 收口对应轮次，兼容起点在窗口外的情况；
- 重建结束后只保留锚点消息仍在本页、或仍处于 running 的轮次，避免把窗口外不可见脚注计入历史前缀；
- `prependHistory` 仍从已拼接的完整事件日志重建，不引入基线，保持现有分页边界。

该方案复用已经与 `lastSequence ↔ messages ↔ turns` 一起持久化的可重放检查点，不新增状态源。

## 数据流与不变式

### 版本

```text
PGC listVersions
  → versionsToVersions
  → 以 index 求 latest
  → pending 完成 / 出新版本 / 冷加载 / 热刷新 四路决策
  → 同一次 set 写 activeVersionId 与 versions[].current
```

- `versions[].current` 只表示前端当前预览选择，必须与 `activeVersionId` 一致。
- `await` 后继续校验 `currentProjectId`，丢弃过期项目响应。

### 轮次

```text
持久化 turns ───────────────┐
                           ├→ rebuild(最新事件窗口) → 可见 messages + 对齐后的 turns
REST 最新事件页 ────────────┘
```

- 输入与输出均为新数组、新对象，不修改持久化快照。
- 有 `runId` 的事件优先精确更新同一轮；缺失时才回退到最后一个 running 轮。
- 已结束但没有可见消息锚点的轮次不进入本页 `historyTurnCount`。
- `prependHistory` 的 live 尾部拼接语义保持不变。

## 测试策略

1. 先把现有“冷启动信任 current”的测试改为“冷启动选择最高 index”，确认旧实现失败。
2. 补充无序版本列表用例，防止再次依赖数组末位。
3. 构造持久化完成轮次，其 `run.started` 不在最新事件页、锚点 AssistantMessage 在页内，确认
   `seedHistory` 旧实现丢失脚注元数据。
4. 补充窗口内同一 `runId` 的事件重放不会复制轮次。
5. 保留并运行现有热刷新手动选择、pending、历史翻页与 live 尾部测试。

## 非目标

- 不改变用户在当前页面手动切换版本后的热刷新行为。
- 不在刷新时自动加载全部历史事件。
- 不推断新的后端字段或给 `is_current` 增加别名。
- 不调整脚注样式、文案或计时格式。
