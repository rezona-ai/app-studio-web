# 分组框参与拖拽边缘对齐

日期：2026-08-19
状态：已批准（2026-08-19 Nick 拍板范围：只做拖动时对齐，缩放另开回合）
前置：`2026-08-04-canvas-align-guides`（四线对齐的纯几何与约束）、`2026-08-12-canvas-ux-refinements`（去中线、阈值按屏幕像素、Alt 临时绕过）、`2026-08-18-group-as-card-selection`（组卡升格；本 spec 正面接管它「明确不做」里的那一条）、`2026-08-19-group-card-selection-polish`（同帧位移与 `livePositions` 的权威坐标口径）

## 目的

Nick：**分组框也要支持边缘对齐**。今天拖框完全不吸附 —— 框是画布上最大的那个矩形，恰恰是最需要对齐的东西，一堆框摞在一起全靠手眼对齐。

## 被推翻的既有约束

`2026-08-18-group-as-card-selection` 的「明确不做」第一条：**「组卡参与拖拽对齐吸附（`align-guides` 今天刻意不含框，本回合不扩）」** —— 本 spec 接管它，那条作废。

落在代码上是 `AssetCanvas.tsx` 的 `beginDrag`：
```
if (groupDragRef.current.length > 0) candidatesRef.current = [];   // 带框的拖拽整体不吸附
else snapshotCandidates();
```
以及它上方那段注释给出的**技术性**理由（不是产品决策）：

> 框的渲染位置被写上 dx/dy 而成员跟随用的是不含 dx/dy 的坐标（两者错位）、画出指向陈旧位置的辅助线、松手时落的 delta 与渲染差几像素（框弹回）。

这条理由今天**依然成立**，所以本回合的真正工作不是「把闸门打开」，而是先把「成员跟随谁的坐标」这件事补齐 —— 打开闸门只是最后一行。

## 决策

### 决策 1：框作为**一个整体**参与，口径与卡片完全一致

- 移动矩形 = **框自己的几何**（`group.x/y/w/h`）；混合选区（框 + 散卡）沿用既有的整组包围盒。框内成员**不参与**移动矩形的计算 —— 与一键整理「框合成为一个固定尺寸节点」同一个抽象（`2026-08-17-tidy-groups-as-boxes-design`）。
- 四线口径不变（每轴只取起始边 / 结束边，**不加中线**）；阈值仍是 `SNAP_THRESHOLD_PX / zoom`；10px 网格吸附照旧由 RF 的 `snapToGrid` 负责；总闸（对齐开关）与 Alt 临时绕过一并生效 —— 不为框新造任何判据。
- 辅助线渲染层（`AlignGuides`）画的是画布坐标的线，与节点类型无关，**一行不改**。

### 决策 2：候选集要排掉「被拖的框的全体成员」

`snapToRects` 已排掉移动矩形自身、`applyDragSnap` 已排掉整组拖拽里的每个被拖节点。但**成员卡不在「被拖节点」里**（RF 不认识它们，是我们逐帧代为平移的），不排掉就会出现：框的内边缘与某张成员卡只差几像素 ⟹ 框吸在**自己的内容**上、一步也挪不动。这与既有那条「选区成员不能互相当参照 —— 否则整组永远吸在自己身上」是同一条依据。

**别的**框的成员卡仍是候选：那些卡在画布上就是卡，框边对齐到它的左缘是合理诉求，不为此加特例。

### 决策 3：框的尺寸从**数据**取，不靠量测回落

`visibleRects` / `sizeOf` 今天都是 `measured?.width ?? cardSize(data.asset.kind)`。框节点没有 `data.asset`，回落值是资产卡的标称尺寸 —— 一旦 `measured` 缺席（首帧、离屏刚挂载），框会被当成一张 180px 的卡去比对，吸到莫名其妙的线上。故这两处都改成**框优先读 `data.group.w/h`**，与 `rf-nodes.ts` 早已立下的契约一致（「框的尺寸由数据驱动，不靠 RF 量测」）。

### 决策 4：成员跟随**吸附后**的坐标（本回合的核心）

不变式：**`渲染坐标 = RF 的原始拖拽坐标 + 本帧吸附偏移`**。

`applyDragSnap` 每帧就着原始坐标算出 `dx/dy` 并改写位置变更（改写结果进 `rfNodes` = 渲染坐标），偏移记在 `lastDeltaRef`；而 `livePositions` 取的是 RF 回调给的**原始**坐标（`getEventHandlerParams` 直接读 `dragItem.position`，只过了网格吸附）。两者相差正好一个 `lastDeltaRef` —— 于是：

- `followMembers` 按原始坐标算 step ⟹ 成员比框少走一个吸附偏移，框吸住的那一下成员**整批错位**；
- `endDrag` 按原始坐标算总位移 ⟹ 落库值与渲染值差一个偏移，松手瞬间**框弹回**。

修法：`livePositions` 给回调坐标**加上本帧吸附偏移**。顺序是成立的 —— `XYDrag.updateNodes` 每帧先 `updateNodePositions`（经 `handleNodesChange`，那里算完偏移并写 `lastDeltaRef`）再同步调 `onNodeDrag`，故读到的偏移恒属本帧。

配套一处：松手帧 `applyDropOffset` 把偏移补进 `dragging:false` 的变更后，当前实现**立刻把 `lastDeltaRef` 清零**，而紧随其后的 `endDrag` 正要用它 ⟹ 改为由 `endDrag` 消费后清零，`beginDrag` 起手复位。清零点从「写入方」移到「消费方」，不变式因此在整个手势内都成立。

## 约束

- 纯几何仍下沉在 `src/lib/align-guides.ts`（无副作用、不认识 RF），组件只接线；框的尺寸取数是纯函数的一部分，单测覆盖。
- 位置归前端所有、坐标回写路径（散卡批量端点 / 框逐个 `updateCanvasGroup`）、撤销条目形状**一律不变**：本回合只改「落哪个坐标」，不改「怎么落」。
- 不引入新令牌 / 新动效：辅助线沿用既有那层。
- 不动框内相对布局与框的 w/h（拖动是刚性平移）。

## 明确不做

- **缩放把手的吸附**（Nick 拍板另开回合）：缩放走的是 `GroupNode` 自己的 window 监听、不经 RF 拖拽链，要另接一套「被拖的那条边吸到邻近同名边」的判定与辅助线。
- **方向键微调时吸附**：微调的语义就是「精确走 N 像素」，叠吸附会让它不可预测（卡片今天也不吸）。
- **中线对齐**：`2026-08-12` 刻意去掉的，不因为框大就复活。
- **框与框之间的等距分布（distribute）**：不在本回合。

## 成功标准

1. 拖一个框靠近另一个框 / 一张卡：出辅助线并吸附，手感与拖卡一致（单测锁「拖框时候选集照旧取到」）。
2. 框吸住的那一帧，**成员与框同步**（单测锁「本帧成员位移 = 框位移 + 吸附偏移」）。
3. 松手落库的框位移**含吸附偏移**，框不弹回（单测锁）。
4. 框**不会吸在自己的成员上**（单测锁「候选集排掉被拖框的成员」）。
5. 关掉对齐开关 / 按住 Alt：框与卡一样不吸（既有两条判据无需改，回归用例仍绿）。
6. `pnpm lint` / `tsc --noEmit` / `pnpm test` / `pnpm test:tz` 全绿。
