# 画布输入与浏览：拖文件进画布 · 常驻新增入口 · Lightbox 翻页

> 状态：设计稿 · 2026-08-04
> 关联：P2 第二组。第一组「可靠性」已落地（`2026-08-04-canvas-persist-reliability.md`）。
> 同期未做：P2 的「键盘手感」「任务可见性」；「取消生成 / 预估消耗」等后端端点
> （2026-08-05 更新：取消**后端明确不做**，估价端点已提供）。

## 目的

三处都是**基本期待的缺席**，成本都很低。

### 一、不能把文件拖进画布

全仓库 `onDrop` 只出现在 `ImportProjectModal`。画布只支持**粘贴**（`useCanvasPaste`）——
从 Finder 拖一张图到画布上，什么都不会发生。画布是拖放最天然的靶子。

上传链路本身是齐的：`validateUpload(files, UPLOAD_POLICY.canvas)` → `uploadAsset(file, opts?)`，
且 `uploadAsset` 的 `opts` 已支持 `spawnAt`（双击空白处新增走的就是它）。所以缺的只有 DOM 事件这一层。

### 二、新增资产的发现性挂在空态文案上

`CanvasEmptyState` 教用户「双击新增」。一旦画布有了资产，空态消失，这句话再也不出现——
新用户此后不会知道双击能新增。而工具条上有整理、小地图、列表、属性、缩放、指针工具，
**独缺最核心的「新增」**。

### 三、Lightbox 不能翻页

`MediaLightbox` 只按 `store.lightbox.assetId` 渲染单个资产，无 ←/→。
生成 4 张候选图要开关四次才能比完——而选片是这个产品最高频的动作之一。

## 约束

1. **拖放落在鼠标松手处**：复用 `uploadAsset` 已有的 `spawnAt`（与双击空白处新增同一口径）；
   多文件从落点开始级联避让，不叠在一起。
2. **拖放复用既有上传管线**：`validateUpload(UPLOAD_POLICY.canvas)` 校验、`UPLOAD` 码 Toast 报拒绝原因，
   与粘贴逐字一致。**不新增第二套上传路径**。
3. **拖放要有可见反馈**：拖到画布上方时给一层提示（拖放区高亮），否则用户不知道松手会不会生效。
   仅在拖的是**文件**时出现（拖画布内的卡片不该触发）。
4. **「+」不新增菜单种类**：点击打开既有 `AddAssetMenu`（双击空白处那一个），落位取视口中心。
   按钮保持 `raised` 实心强调，但尺寸比其余工具条按钮小一档（36 vs 40，图标 18 vs 20）——
   实心块在一排 ghost 图标里本就更抢眼，同尺寸会显得过大（真机反馈后改）。
5. **翻页范围 = 当前画布可见的可预览资产**：跟随类型筛选与搜索命中同一份列表（`visibleAssets`），
   只取 `image / video / 3d` 且 `status === 'ready'`。用户看到什么就在什么里翻。
6. **翻页不做环绕**：到头即禁用箭头（环绕会让人分不清「转了一圈」还是「没动」）。
7. **键盘 ←/→ 与按钮等价**；`Escape` 关闭的既有行为不变。
8. **纯逻辑下沉**：可翻页列表的推导、上一个/下一个的求解是纯函数进 `lib/`；DOM 事件与渲染留在组件。
9. UI 复用既有令牌与基础组件：「+」用 `IconButton`，箭头沿用 Lightbox 现有关闭按钮的白色半透明圆钮样式，
   拖放高亮用 `--color-teal` + `--color-teal-soft`，不新增色值、不新增一次性 keyframes。

## 成功标准

1. 从 Finder 拖一张图到画布 → 卡落在**松手位置**，与粘贴走同一条上传链路。
2. 拖多个文件 → 依次落位、互不重叠。
3. 拖入不支持的文件（如 .exe）→ 与粘贴同款 `UPLOAD` Toast，说明拒绝原因。
4. 拖文件进入画布区域时出现拖放提示，离开 / 松手后消失；**拖画布内的卡片不触发**该提示。
5. 工具条最左出现常驻「+」，点击打开既有新增菜单，新卡落在视口中心。
6. Lightbox 出现 ←/→ 按钮与键盘支持，在**当前画布可见**的可预览资产间翻页。
7. 类型筛选只开 Image 时，翻页序列里没有视频 / 3D。
8. 到首/末端箭头禁用，不环绕。
9. 单张可预览资产时不显示箭头（没什么可翻）。

## 方案

| 文件 | 职责 |
|---|---|
| `src/lib/lightbox-nav.ts`（新） | 纯函数：`previewableAssets(assets)` 与 `stepAsset(list, currentId, dir)` |
| `src/components/canvas/MediaLightbox.tsx` | 接 ←/→ 按钮与键盘；列表由 props 传入（组件不自己算可见性口径） |
| `src/components/canvas/AssetCanvas.tsx` | `onDragOver / onDragLeave / onDrop` + 拖放高亮层；工具条加「+」；把可翻页列表传给 Lightbox |
| `src/lib/upload-policy.ts` | 复用现有 `validateUpload`，不改 |
| `src/lib/popover-position.ts`（新） | `clampPopover` —— 浮层从触发点展开并夹进视口；`AddAssetMenu` 接上 |

拖放高亮做成画布容器内的一层 `absolute inset-0 pointer-events-none` 边框 + 柔光，
用 `dragDepth` 计数抵消 `dragenter/dragleave` 在子元素间冒泡造成的抖动（拖过卡片时不闪）。

## 明确不做

- **并排对比模式**：翻页已解决「四张候选开关四次」的主痛点；对比是另一个形态（选两张、布局、同步缩放），按 YAGNI 先不堆。
- **拖放到指定卡片上做派生**（拖图到卡上 = 以它为源生成）：语义含糊，且与既有「卡片贴边 +」入口重复。
- **拖放整个文件夹**：`webkitGetAsEntry` 递归目录是另一档复杂度，本轮只收顶层文件。
- **Lightbox 里删除 / 重命名**：Lightbox 是只读预览面，编辑动作留在画布与属性面板。

## 真机验收（2026-08-04，dev :3010，项目 Star Whisper-v82，32 张卡）

手法：真 `File` + 真 `DataTransfer` 走完整 `dragenter → dragover → drop`；状态经仓库自带的
dev 调试句柄 `window.__store` 读取。

已验：

1. **拖真图进画布**：卡落在松手处 —— 松手点 `(900, 300)`，卡片中心 `(900, 310)`（差 10px 是网格吸附），
   走通上传落到 `status: ready`，与粘贴同一条管线。
2. **拖放提示**：拖入时出现青色虚线框，松手后消失。
3. **拖画布内的卡片不触发提示**：`dataTransfer.types` 只有 `text/plain` 时高亮不出现。
4. **拒绝路径**：拖 `payload.exe` → 资产数不变，`UPLOAD` Toast 列出允许的格式，与粘贴逐字一致。
5. **工具条「+」**：出现在最左、raised 强调；点开是既有新增菜单（Generate / Add source 两组），
   `spawnAt` 取到视口中心 `(1130, 190)`。
6. **Lightbox 翻页**：←/→ 圆钮出现在两侧、与关闭钮同款；点右箭头与按 `→` 等价，`←` 能退回。
7. **跟随类型筛选**：只开 Image 时，从第一张一路 `Next` 走了 **14 步**，全部 `kind === 'image'`（无视频 / 3D），
   首项 `Previous` 禁用、末项 `Next` 禁用（不环绕）。

**未验到的**：

- **拖多个文件的级联避让**：合成 `DataTransfer` 塞多文件可以做，但落位避让本身由 `avoidOverlap` 保证、
  已有单测；本轮只验了单文件的落点。
- **拖文件夹**：设计稿里明确不做，`filesFromDataTransfer` 会剔除目录项（单测覆盖）。

**收尾**：验收上传的 `drop-test.png` 已删除，重载后确认画布仍是原来的 32 张卡、四行布局未变。

## 追加修复（真机反馈，2026-08-04）

Nick 在真机上指出两点，都已修：

1. **「+」按钮显得过大**：物理尺寸与其余工具条按钮一致（都是 40×40），但 `raised` 是恒浅色实心块，
   在一排 ghost 图标里视觉重量本就更高，同尺寸就显得大。**保留 raised 配色**（强调是有意的），
   只把尺寸降一档：`size-9`（36px）。
   **图标仍是 20px** —— 一度跟着缩到 18，Nick 立刻指出加号线宽和邻居对不齐：
   全套图标都是 20×20 viewBox 里 `stroke-width: 1.5`，缩到 18 等于把线宽压成 1.35。
2. **菜单弹出位置不对**：`AddAssetMenu` 一直是 `left/top` 死定位 + `origin-top-left`，**从不夹取视口**。
   双击画布中部时看不出问题，而工具条在画布底部，从按钮往下展开会整个掉出屏幕。
   新增纯函数 `clampPopover`：空间不够就以触发点为边界翻到另一侧，翻完仍溢出则夹到 12px 边距内，
   并回吐 `transform-origin` 让缩放动画从触发点那一角长出来。**这条同时修掉一个既有隐患** ——
   在画布靠下位置双击空白处开菜单，此前同样会溢出屏幕。
   真机复测：菜单 `top 335 / bottom 673`（视口高 728）完整在屏内，`transform-origin` 为 `left bottom`。
