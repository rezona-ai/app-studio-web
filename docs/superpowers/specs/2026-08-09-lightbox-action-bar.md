# Lightbox 底部动作条（P1-1）

日期：2026-08-09 · 分支 `feat/lightbox-action-bar` · 来源：`docs/superpowers/2026-08-07-canvas-review-handoff.md` 的 P1 第 1 项

## 目的

评审对画布的整体判断是：**「信任 / 可追溯 / 不丢东西」这条主轴已达行业领先，「高频创作循环的爽感」仍是行业平均**，
而爽感的缺口不在功能少，在**闭环没通** —— 「从 8 张里挑 2 张 → 打个标 → 把剩下的收起来」这条路走不通。

本项解的是这条路的**第一段：挑**。评审的原话值得照抄，因为它否掉了一个看起来更显然的方案：

> 真实缺口**不是**「并排对比」（画布本身就是栅格），而是**「进去之后不能动作」**。这是选片闭环的关键一刀。

今天的 `MediaLightbox` 只能看和翻：Esc 关、←/→ 翻、到头禁用。看中一张想拿它再生成、看到一张想删，
都必须先关窗、在画布上重新找到那张卡、再右键。**「关窗 → 重新找」这个动作本身就是闭环断掉的地方** ——
一批 8 张新图，用户要在浏览态与操作态之间来回切 8 次。

## 成功标准

1. 打开 lightbox 后，**不关窗**就能对当前这张做三件事：删除、以此派生、下载。
2. 连续取舍不被打断：删一张自动翻到下一张，可以一路 `→ → Delete → →` 走完一批。
3. 知道自己在哪：显示 `3 / 14` 位置指示，分母与实际能翻到的张数一致。
4. 删错了能救回来（复用既有的延迟删除窗口 + Toast 撤销，不新造机制）。
5. 关窗后画布回到进来之前的样子 —— 浏览不改变用户此前的选中意图。

## 约束

1. **不新增后端字段、不改任何端点。** 三个动作全部复用既有 action / 工具函数。
2. **不引入新的按钮种类 / 色值 / keyframes**（CLAUDE.md「UI/UX 范式」是约束不是建议）。
   动作条用既有 `IconButton` + `FigIcon`（`figAsset.trash` / `figAsset.plus` / `figAsset.download`）。
3. **不碰画布选中态。** `openLightbox` 现在完全不写 `selectedIds`（`store/index.ts` 的 `openLightbox`），保持不变。
4. **不做「保留 / 收藏」。** 见下「明确不做」。
5. **翻页口径不新造。** 沿用 `previewableAssets(navList)`，`navList` 仍由 `AssetCanvas` 渲染 `<MediaLightbox navList={visibleAssets} />` 处传入
   —— 「哪些卡当前可见」是画布的知识，组件不自己算（既有注释，两处口径漂移过一次的教训）。

## 决策（盘问结论）

### 1. 动作集 = 删除 + 以此派生 + 下载。**不做「保留」**

评审写的是「保留 / 删除 / 以此派生」，但**「保留」在这套代码里没有落点**：没有收藏字段
（`CanvasItemData` 无 tags/favorite，`tags` 只存在于素材库只读的 `LibraryAssetData`），
也不存在「未保留就会消失」的机制 —— 资产本来就都留着。强行加一个按钮只会是装饰。

「保留」的真实含义是 P1 第 2 项（收藏 / 打标）。等那项落地后往动作条里加一个键即可，本轮预留位置。

下载纳入是因为它**几乎零成本**（`downloadAsset` + `canDownloadAsset` 现成，含失败 Toast 路径），
而「看中了想存一份」正是浏览态里最自然的第三个念头。

### 2. 删除**不弹确认**，直接进延迟窗口

`requestDeleteAssets` 已经是「立即从画布移除 + `DELETE_GRACE_MS` 延迟窗口 + Toast 撤销按钮」，
确认弹窗是它之上的第二层保险。lightbox 里去掉这层，理由：

- 选片要连删好几张，每张弹一次会把浏览流敲碎；
- `DeleteAssetModal` 是 `z-40`，lightbox 遮罩是 `z-30` —— 弹窗会**盖住正在看的那张图**，
  用户在「看图」和「读弹窗」之间被强行切换；
- 撤销机制已经存在且更适合高频取舍：删错了 Toast 上点一下就回来。

> ⚠️ 右键菜单**保持现状**（单选直接删、多选弹弹窗）。两处行为不同是有意的：
> 画布上按 Delete 时用户可能选着一批卡而注意力不在上面，lightbox 里则是「正看着这一张」。

### 3. 删除后焦点：下一张 → 上一张 → 关窗

删掉当前这张后：能翻到下一张就翻下一张；已经是最后一张就退到上一张；序列空了就关窗。
**「下一张是谁」必须在删除前算好** —— 删完当前 id 已不在列表里，`stepAsset` 会返回 `null`（`findIndex < 0`）。

### 4. `Delete` / `Backspace` 归 lightbox，画布监听让位

这是本项最容易踩的一处。`AssetCanvas` 里那个调用 `shouldTriggerCanvasDelete` 的 effect 挂着 **window 级** keydown：
按 `selectedIds` 删，单选直删、多选弹确认。lightbox 开着时按 Delete，今天会去删**画布上选中的卡**
（可能根本不是正在看的那张），多选时还会弹出确认框盖住 lightbox。

按浮层语义，lightbox 开着时删除归它。实现上在画布那个监听里加「lightbox 开着就返回」的守卫，
lightbox 自己的监听处理删除。**这条必须有测试钉住**，它是无声出错的那类 bug：
画布多选 3 张 + lightbox 开着 + 按 Delete → 今天删 3 张、期望删 1 张（正在看的）。

### 5. 「以此派生」复用 AddMenu，`openGenForm` 顺带关窗

画布上派生走的是 `openAddMenu({x, y, sourceId})` → 用户选目标类型 → `openGenForm` / `openDerived3dForm`。
lightbox 里同样走这条，不另造一套类型选择。

`AddAssetMenu` 实测是菜单 `z-50` + 自身遮罩 `z-40`（`z-[56]` 是画布浮动菜单那一档，此处不是），**盖得住** lightbox 的 `z-30`，所以选类型期间 lightbox 可以留着。
真正该关窗的时机是**表单打开那一刻**：生成会先落 `pending_` 占位卡，而 lightbox 只渲染
`status === 'ready'`（`MediaLightbox` 的渲染守卫那几行早返回）——占位卡在 lightbox 里根本显示不出来，
留着窗只会让用户看着一张旧图、不知道新卡落在哪。

故在 `openGenForm` / `openDerived3dForm` 两个 action 里顺带 `lightbox: null`。
放在 action 而不是组件里，是因为这是**语义上的不变式**（「生成表单打开 ⟹ 已离开浏览态」），
不是某个按钮的局部行为；其余调用方（retryGeneration 等）触发时 lightbox 本就是关的，清一次无害。

### 6. 位置指示分母 = 可翻页序列长度

显示 `3 / 14` 中的 14 是 `previewableAssets(navList).length`，**不是**画布上资产总数。
指示与翻页行为必须同源，否则「显示 /20 但翻到 14 就到头」。
这意味着筛选 / 搜索会改变分母 —— 那是对的，因为翻页口径本来就跟着筛选走。

### 7. 不可用的动作**禁用而非隐藏**

派生资格走既有 `canDeriveFrom`（与 NodeCard、AddAssetMenu 同一处判据），下载走 `canDownloadAsset`。
不满足时按钮 `disabled` 并保留 Tooltip 说明，不隐藏 —— 与「翻页到头禁用而非环绕」同一取向：
**位置稳定比少一个灰按钮重要**，动作条不该在翻页时跳来跳去。

## 布局与视觉

- 动作条在**媒体下方独立一行**，不覆盖媒体。video 有原生 controls 在自己底部，压上去会打架。
- 外观沿用 lightbox 内既有的深色浮层语汇（`bg-white/10` + `hover:bg-white/20` + `rounded-full`，
  与翻页 / 关闭按钮同款）—— lightbox 是全黑遮罩上的浮层，这里**不适用**画布的 `--color-surface` 系列。
- 位置指示用 `--font-mono`（等宽数字，翻页时数字不跳宽）。
- 只有一张时动作条照常出现；**只有翻页按钮**依赖 `nav.length > 1`（既有逻辑）。
- 进出场跟随 lightbox 既有的 `modal-pop` / `data-closing`，不新增动画类。

## 必测

1. 三个按钮各自调到正确的 action，且**不冒泡到遮罩**（遮罩 `onClick` 是关窗，冒泡会点一下就关）。
2. 删除后翻到下一张；删最后一张退到上一张；删光了关窗。
3. **lightbox 开着 + 画布多选**时按 Delete：只删正在看的那张，不弹确认弹窗，不动其余选中。
4. lightbox 关着时按 Delete：画布既有行为**不变**（单选直删 / 多选弹窗）—— 防止守卫写反。
5. `3 / 14` 的分母跟随筛选变化；翻页时分子跟着走。
6. 不可派生 / 不可下载的资产：按钮 `disabled`，点击不触发 action。
7. 派生：点按钮开 AddMenu；`openGenForm` 后 `lightbox === null`。
8. 翻页**不改变** `selectedIds`（钉住约束 3）。
9. 无障碍：三个按钮各有 `aria-label`；位置指示不进 a11y 树的可交互序列。

## 明确不做

- **收藏 / 打标（「保留」）** —— 无服务端落点，属 P1 第 2 项。届时往动作条加键。
- **并排对比 / 多选浏览** —— 评审明确说这不是真实缺口，画布本身就是栅格。
- **重命名 / 用作引用** —— 塞进消费型浏览界面会把「选片」这件事冲淡；右键菜单已有。
- **改右键菜单的删除确认行为** —— 两处语境不同，见决策 2 的注。
- **⌘Z 在 lightbox 里的行为** —— 沿用既有全局 undo，不特殊处理。
